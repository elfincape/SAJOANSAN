# 카카오톡 업무포탈 수집기

기존 카카오톡 업무 수집 앱에서 설정합니다. 기존 SQLite 저장 위치와 캡처를 유지합니다. 로그인 시 에이전트가 같은 앱을 열고, 앱의 Python이 수집과 포탈 접수 작업을 별도로 실행합니다.

전송은 기존 업무포탈 인증과 방별 수집 선택을 사용합니다. 사진은 기존 수동 접수의 사진 처리 경로에 들어갑니다. 처음 전송 모드는 확인이며, 이후 모드를 자동으로 설정한 시점부터 고정하는 접수는 조건에 맞으면 처리됩니다. 이전 확인 접수와 운영 데이터의 상태를 소급해서 변경하지 않습니다.

기존 수동 접수의 동일 ID, 상태 조회, 원문·사진 보관, 날짜·대상·상태 검증을 재사용합니다. 등록 및 갱신 후보에 JEV의 복수 의도 신호와 기존 증거 확인이 모두 필요합니다. 확인 대상은 업무포탈 업무 투영에서 제외되고 수집 화면에 판단 근거가 남습니다. 기존 완료나 취소 변경은 자동 반영을 보류합니다.

키 설정은 Supabase Edge Function의 기존 TYPESAFE_API_KEY 또는 JEV_API_KEY를 사용합니다. 로컬 수집기에는 공개 클라이언트 키와 로그인 세션만 보관합니다. 승인된 계정과 우선 운영 범위는 기존 서버 권한 검사를 적용합니다.

- 수집기 상태와 전송 기록은 기존 collector.sqlite3의 추가 테이블에 기록합니다.
- 원문 12,000 UTF-16 단위, 사진 최대 3장과 원본 합계 8 MB 제한을 적용합니다. 초과하는 단독 원문·사진은 로컬에 보관합니다.
- 방 목록·대화·사진은 고정된 kakaotalk-ax 4fb2bc7을 사용합니다. mac-app-ax의 권한·직렬화·결과 확인 지침은 e0817a1의 문서를 따릅니다.
