# 카카오톡 업무 수집기

Finder 앱에서 여는 수집 현황의 **카카오톡 방 목록 가져오기**에서 방을 선택하고 **선택 저장**을 누르면 자동 수집을 시작한다. 첫 수집은 선택한 방의 최근 노출 구간을 포함한다. **수집 화면 열기.webloc**은 앱이 시작할 때 현재 로컬 확인 화면을 가리키도록 갱신한다.

## 저장과 복구

- SQLite에 방별 마지막 관찰, 대화 순서, 메시지와 첨부 ID, 파일 저장 시도와 전송 대기열을 유지한다. 초기 수집 이후에는 최근 24행을 확인한다. 직전 대화와 연결되지 않으면 더 넓은 구간을 확인하고 누락 가능성을 표시한다.
- 사진은 선택한 대화창에서 행과 첨부 순번을 확인한 뒤 카카오톡 사진 뷰어로 연다. 묶음 사진은 뷰어의 **이 사진만 저장**을 사용한다. 저장 대화상자에서 요청 전용 폴더를 확인한 뒤 카카오톡이 제시한 파일명으로 저장한다. 파일 획득을 확인할 수 없으면 해당 첨부를 대기로 내보낸다. 과거 버전의 화면 캡처는 원본으로 내보내지 않는다.
- 맥의 데이터 폴더 아래에 `collector.sqlite3`, `downloads/`, `outbox/`가 있다. 개인 OneDrive 연결은 `native/rclone`과 사용자 전용 `onedrive.conf`의 `kakao` 원격을 사용한다. OneDrive에는 `카톡수집/batches/<batch_id>.json`, `카톡수집/images/<sha256>.<ext>`를 쓴다. 첨부의 상대 경로 기준은 `카톡수집/`이다. 같은 배치의 사진 상태가 바뀌면 같은 JSON을 갱신한다.
- `sent_at`은 해당 AX 행에서 날짜와 시각이 모두 확인될 때만 기록한다. 발신자 표기가 없는 행의 `sender_name`은 null이다.
- 사용자 로그인 세션의 LaunchAgent는 Finder와 같은 앱 번들을 열고 종료 시 다시 시작한다. AC 전원에서는 수집기 프로세스의 수명 동안 시스템 잠자기 방지 요청을 유지한다. 화면 잠금이나 AX 오류 중에는 마지막 정상 관찰을 보존한다.

## 네이티브 브리지

`requirements.txt`에 지정된 kakaotalk-ax 0.9.0을 사용한다. 동일 Python 환경에서 `python build_reader.py <데이터폴더>/native/collector-read <데이터폴더>/native/collector-control`을 실행하면 설치된 upstream의 Swift 소스를 확인한 뒤 제한된 읽기 범위와 사진 저장 동작을 빌드한다. 손쉬운 사용 권한은 Finder에서 실행하는 **카카오톡 업무 수집** 앱의 실제 읽기 결과로 확인한다.

### 다른 기기에서 수집 화면 열기

맥과 휴대폰 또는 PC의 Tailscale에 같은 계정으로 로그인한다. 원격 제어를 켠 맥의 수집 현황에 표시되는 VPN 주소를 다른 기기 브라우저에서 연다. 방 선택, 수집 시작·일시정지, 주기 변경은 기존 수집기와 같은 설정에 적용된다. 카카오톡을 읽으려면 맥이 깨어 있고 카카오톡의 잠금이 풀려 있어야 한다.

원격 기능은 로컬 SQLite의 `private_vpn_enabled` 설정으로 켠다. 수집기는 처음 연결된 Tailscale 사용자 ID와 맥 기기 ID를 보존한다. TCP 18749는 Tailscale의 IPv4 주소와 그 utun 인터페이스에만 바인딩한다. HTTP는 기기 간 WireGuard 터널을 통과한다. 매 요청마다 연결 상대의 IP를 Tailscale에 조회해 같은 사용자의 개인 기기인지 확인한다. 로컬용 접속 키와 LaunchAgent 관리 동작은 원격에서 제공하지 않는다.

포트 번호 없는 기본 주소는 Tailscale Serve의 비공개 HTTP 서비스다. 같은 계정의 VPN 기기에서 수집 현황에 표시된 기본 주소로 접속한다. 전용 구성에서는 맥의 VPN IPv4 주소와 전체 MagicDNS 이름을 모두 사용할 수 있다. 수집기는 Serve 전용 루프백 경로에서 프록시가 전달한 기기의 Tailscale 사용자 ID를 확인한다. 기존 18749 주소도 함께 사용할 수 있다.
