# 이안 카카오 수집 → OneDrive

기존 관리허브 저장소에 함께 관리하는 별도 안드로이드 앱입니다. 관리허브 웹·DB·업무 생성은 수정하지 않습니다. Android 13 이상, 전용 법인폰에서 사용하는 실기기 검증용 버전입니다.

## 먼저 알아둘 범위

- 지정 방의 텍스트 알림은 UTF-8 `.txt`로 저장합니다. 알림 내용은 생략될 수 있어 전체 대화 백업을 뜻하지 않습니다.
- 지정 방의 새 알림 또는 ‘현재 열린 방 사진 수집’으로 **현재 화면에 보이는 사진**을 저장합니다.
- 사진을 실제 파일로 확보하고 주변 대화와 함께 OneDrive에 전송합니다. 알림 썸네일·스크린샷으로 대체하지 않습니다.
- 과거 대화 전체 수집, 화면 밖 사진 회수, 무누락 운영, 정확한 사진별 발신자 연결은 보장하지 않습니다. 같은 이름의 방은 사용하지 마세요.
- 서비스가 종료되면 알림 대기열은 복구되지 않습니다. 이미 확보해 내부 큐에 기록한 사진은 수집을 다시 시작하면 전송을 재시도합니다.
- 수집 화면과 카카오톡을 사용자가 동시에 조작하지 마세요. 화면은 켜두고 잠금을 해제해야 합니다.

## 1. Microsoft 앱 등록 (최초 1회)

관리허브의 기존 비밀 키를 복사하지 않습니다. 공개 클라이언트 앱을 별도로 등록합니다.

1. [Microsoft Entra 관리센터](https://entra.microsoft.com/)에서 앱 등록 → 새 등록을 엽니다. 앱 등록 권한이 있는 디렉터리가 필요합니다. 개인 계정에서 디렉터리/등록 메뉴를 사용할 수 없으면 등록 가능한 조직 관리자 또는 Azure 디렉터리 준비가 필요합니다.
2. 이름은 `이안 카카오 수집`으로 등록합니다. 지원 계정 유형은 **모든 조직 디렉터리의 계정 및 개인 Microsoft 계정**으로 선택합니다. 이 버전의 로그인 대상은 개인 Microsoft 계정입니다. 회사/학교 OneDrive 전용 구현은 아닙니다.
3. 등록 후 개요의 **애플리케이션(클라이언트) ID**를 복사합니다. ‘개체 ID’나 ‘디렉터리 ID’가 아닙니다.
4. 인증 → 고급 설정에서 **공용 클라이언트 흐름 허용**을 켭니다. Device code 흐름을 사용하므로 웹 리디렉션 주소와 클라이언트 비밀 키는 필요하지 않습니다.
5. API 사용 권한 → Microsoft Graph → 위임된 권한에 `Files.ReadWrite`, `offline_access`를 추가합니다. 이 앱에 필요하지 않은 권한은 추가하지 않습니다.
6. ID를 폰 앱에 입력하고 OneDrive 로그인 버튼을 누릅니다. 표시된 코드를 Microsoft 로그인 페이지에 입력하고 사진을 저장할 **개인 OneDrive 계정**으로 동의합니다.

앱은 `offline_access Files.ReadWrite`를 요청합니다. 일반 OneDrive 폴더를 쓰므로 계정 파일 읽기·쓰기 위임 권한이 필요하지만 앱의 업로드 경로는 최상위 `이안카카오/대화방 이름/`으로 고정합니다. 토큰은 폰의 Android Keystore로 암호화해 저장합니다. `이안카카오` 폴더를 미리 만들어도 되고 없으면 앱이 생성합니다. 기존 관리허브 업무자료 폴더는 변경하지 않습니다.

## 2. 앱 설치·권한

개발용 APK를 설치합니다. 최초 설치에는 USB를 사용해도 상시 수집에는 필요하지 않습니다.

```powershell
.\adb.exe install -r "C:\실제경로\ian-kakao-collector-debug.apk"
```

- 앱에서 클라이언트 ID와 수집 방 이름을 한 줄에 하나씩 입력하고 설정 저장을 누릅니다.
- OneDrive 로그인을 마칩니다.
- ‘사진·알림 권한 허용’에서 **모든 사진 허용**을 선택합니다. 일부 사진만 허용하면 새 카카오톡 사진을 읽지 못할 수 있습니다.
- 접근성 → 설치된 앱 → 이안 카카오 수집을 켭니다. One UI에서 제한된 설정이라고 나오면 앱 정보의 메뉴에서 ‘제한된 설정 허용’ 가능 여부를 확인합니다. 회사 정책이 막으면 관리자 설정이 필요합니다.
- 알림 접근 → 이안 카카오 수집을 켭니다. 카카오톡에서도 해당 방의 메시지 알림을 켭니다.
- 앱 배터리는 제한 없음으로 설정하고 절전/초절전 대상에서 제외합니다.
- 벽면 충전기에 연결합니다. 개발자 옵션의 **충전 중 화면 켜짐 유지**를 사용할 수 있습니다. USB 데이터 연결은 필요하지 않습니다. 자동 잠금과 화면 꺼짐으로 수집이 중단될 수 있습니다.
- ‘수집 시작’ 후 테스트 방에 사진을 받습니다. 수동 점검은 ‘현재 열린 방 사진 수집’에서 방을 선택하고 해당 방으로 이동합니다. 앱은 제목 일치 확인 후에만 사진을 조작합니다.

사진 저장 중 뷰어의 창·화면 구성이 바뀌거나 저장 후 원래 허용된 방으로 돌아오지 못하면 업로드하지 않고 중단합니다. 이 보호 동작도 실기기에서 확인해야 합니다.

자동 방 열기가 One UI에서 차단되거나 방 제목 ID가 맞지 않으면 수집이 중단됩니다. 이 경우 고정 좌표로 강행하지 말고 해당 단말의 화면 요소를 확인해 수정해야 합니다.

## 3. 저장 결과

```text
이안카카오/
  김해 배차방/
    2026-10-22_15-20-30_123_<접수UUID>_01.jpg
    2026-10-22_15-20-30_123_<접수UUID>_02.jpg
    2026-10-22_15-20-30_123_<접수UUID>_대화.txt
    2026-10-22_15-21-10_456_<다른접수UUID>_대화.txt
```

파일명은 **한국 시간(Asia/Seoul)의 수집 시각**이며 원래 메시지 발신 시각이나 촬영 시각이 아닙니다. 밀리초·전체 접수 UUID·묶음 순번으로 같은 시각의 파일 덮어쓰기를 방지하며 재시도에도 같은 이름을 사용합니다. 대화방 이름의 금지 문자·예약어·과도한 길이는 정리하고 고유 해시를 붙입니다. 같은 이름의 별개 방은 여전히 지원하지 않습니다. 등록할 방끼리 대소문자 차이·문자 정리 때문에 같은 OneDrive 폴더명이 되면 설정 저장을 거부합니다.

사진은 카카오톡에서 실제로 저장한 JPG·PNG·WEBP의 바이트를 변경하지 않고 업로드합니다. 알림에 포함된 대화와 사진 주변 화면 텍스트는 날짜·시간이 붙은 UTF-8 `_대화.txt`로 저장하며, 방 이름·수집 시각·알려진 발신자와 원문 줄바꿈을 보존합니다. 사진 접수에 텍스트가 없으면 사진만 저장합니다. 사진 파일 확보에 실패한 건을 텍스트 성공으로 대신 처리했다고 표시하지 않습니다.

**새 수집분은 OneDrive에 JSON을 올리지 않습니다.** 재시도에 필요한 내부 접수정보만 폰의 앱 전용 저장소에 JSON으로 유지합니다. AI 분석·분류·관리허브 업무 생성은 하지 않습니다. 이전 버전이 이미 올린 JSON은 자동 이동·삭제·변환하지 않습니다.

전송 실패 시 앱 상태에 오류를 표시하고 내부 대기 파일을 유지합니다. 업로드 완료 후 앱 내부 사진 사본만 정리하며 카카오톡이 저장한 사진은 지우지 않습니다. 앱 삭제·앱 데이터 초기화는 미전송 사진도 삭제하므로 대기 0건을 확인하기 전에는 하지 마세요. 완료 후 폰에 남는 카카오톡 저장 사진과 접수 이력의 보관 기간은 운영 중 별도로 관리해야 합니다.

## 4. v0.2.0 업데이트

- 기존 앱을 삭제하거나 데이터를 초기화하지 말고 같은 개발 서명의 APK를 `adb install -r`로 업데이트합니다.
- Entra API 사용 권한에 Microsoft Graph **위임된 `Files.ReadWrite`**를 추가합니다. 이전 `Files.ReadWrite.AppFolder`만으로는 최상위 폴더에 저장할 수 없습니다.
- 수집 중지 후 앱에서 **OneDrive 로그인**을 다시 눌러 새 권한에 동의합니다. 이전 범위의 토큰은 전송 전에 차단합니다.
- 이전에 업로드한 앱 전용 폴더의 파일은 이동·삭제하지 않습니다. 아직 로컬 대기 중인 건은 새 구조로 업로드합니다.
- v0.2.0은 사진과 대화 파일의 저장 규칙을 변경합니다. PDF·엑셀 같은 일반 첨부파일 수집 기능을 추가한 것은 아닙니다.

## v0.2.1 로그인 복구

브라우저 승인 후 앱이 DNS·일시적 통신 오류 한 번으로 확인을 끝내던 문제를 수정했습니다. 로그인 코드의 유효 시간 안에서 DNS·연결·시간 초과 및 HTTP 408/429/5xx를 재시도합니다. 토큰을 받은 뒤 OneDrive 계정 조회가 실패하면 받은 토큰을 유지해 조회만 재시도하며, 승인 거부·계정 불일치·인증서 오류는 계속 강행하지 않습니다.

브라우저에서 ‘모두 완료했습니다’가 나오면 수집 앱으로 돌아와 맨 아래 **OneDrive 로그인 완료**를 확인하세요. 로그인 확인은 앱 화면 재생성 때문에 취소하지 않지만, OS가 앱 프로세스를 종료하면 다시 로그인해야 합니다. 지속적인 DNS/네트워크 차단 자체를 해결하는 기능은 아닙니다. 이 동작은 모의 네트워크에서 검증했으며 실제 폰에서 재확인이 필요합니다.

## v0.2.2 원본 파일 저장·사진 제목 인식 수정

OneDrive에는 이미지 파일과 TXT만 올립니다. 사용자 단말에서 확인된 카카오톡 `toolbar_default_title_text`의 `content-desc`로 방 이름을 인식하도록 수정했습니다. 메시지 본문을 방 이름으로 대신 사용하거나 허용 목록을 우회하지 않습니다.

사진 수집 상태와 업로드 상태를 별도 줄로 표시합니다. 텍스트 전송 완료가 사진 수집 오류를 덮어쓰지 않습니다. 사진 처리 실패 시 어느 단계인지 확인할 수 있습니다. 실제 사진 자동 저장과 업로드는 이 APK를 설치한 법인폰에서 다시 확인해야 합니다.

## 5. 실기기 합격 기준

1. 테스트 방에 새 단일 사진을 보내고 OneDrive 파일이 열리는지 확인합니다.
2. 새 묶음사진 세 장을 보내고 실제 이미지 파일 세 개가 모두 열리는지 확인합니다.
3. 네트워크를 끊고 수집한 뒤 재연결 시 대기 건이 업로드되는지 확인합니다.
4. 수집 중지 후 새 사진이 수집되지 않는지 확인합니다.
5. 등록하지 않은 방은 열거나 수집하지 않는지 확인합니다.
6. 앱을 재시작하고 수집 시작 후 기존 대기 파일이 복구되는지 확인합니다.
7. 화면 잠금·권한 해제·배터리 제한 시 중단 상태를 확인합니다.

이 검증을 마치기 전에는 퇴사자 업무를 완전히 대체하는 무인 수집기로 사용하지 않습니다. 실제 단말의 ADB 사진 저장·파일 반출, 앱 설치와 이전 버전 OneDrive JSON 저장은 사용자가 확인했습니다. v0.2.2의 사진 자동 저장·이미지/TXT 직접 업로드는 실제 폰에서 재확인이 필요합니다.

## 빌드

JDK 17, Android SDK 35, Build Tools 34.0.0, Gradle 8.10.2를 사용합니다. Android Studio에서 이 폴더를 열거나 다음처럼 빌드합니다.

```bash
gradle --no-daemon assembleDebug lintDebug
```

출력: `app/build/outputs/apk/debug/app-debug.apk`. 개발용 서명이며 배포 키는 저장소에 넣지 않습니다. Gradle wrapper가 포함되어 있으므로 `./gradlew` 또는 Windows의 `gradlew.bat`를 사용할 수 있습니다.
