# 이안 카카오 수집 → OneDrive

기존 관리허브 저장소에 함께 관리하는 별도 안드로이드 앱입니다. 관리허브 웹·DB·업무 생성은 수정하지 않습니다. Android 13 이상, 전용 법인폰에서 사용하는 실기기 검증용 버전입니다.

## 먼저 알아둘 범위

- 지정 방의 텍스트 알림은 `kind: notification` 접수 JSON으로 따로 저장합니다. 알림 내용은 생략될 수 있어 전체 대화 백업을 뜻하지 않습니다.
- 지정 방의 새 알림 또는 ‘현재 열린 방 사진 수집’으로 **현재 화면에 보이는 사진**을 저장합니다.
- 사진을 실제 파일로 확보하고 주변 대화와 함께 OneDrive에 전송합니다. 알림 썸네일·스크린샷으로 대체하지 않습니다.
- 과거 대화 전체 수집, 화면 밖 사진 회수, 무누락 운영, 정확한 사진별 발신자 연결은 보장하지 않습니다. 같은 이름의 방은 사용하지 마세요.
- 서비스가 종료되면 알림 대기열은 복구되지 않습니다. 이미 확보해 내부 큐에 기록한 사진은 수집을 다시 시작하면 전송을 재시도합니다.
- 수집 화면과 카카오톡을 사용자가 동시에 조작하지 마세요. 화면은 켜두고 잠금을 해제해야 합니다.

## 1. Microsoft 앱 등록 (최초 1회)

관리허브의 기존 비밀 키를 복사하지 않습니다. 공개 클라이언트 앱을 별도로 등록합니다.

1. [Microsoft Entra 관리센터](https://entra.microsoft.com/)에서 앱 등록 → 새 등록을 엽니다. 앱 등록 권한이 있는 디렉터리가 필요합니다. 개인 계정에서 디렉터리/등록 메뉴를 사용할 수 없으면 등록 가능한 조직 관리자 또는 Azure 디렉터리 준비가 필요합니다.
2. 이름은 `이안 카카오 수집`으로 등록합니다. 지원 계정 유형은 **모든 조직 디렉터리의 계정 및 개인 Microsoft 계정**으로 선택합니다. 이 버전의 로그인 대상은 개인 Microsoft 계정입니다. 회사/학교 OneDrive 전용 구현은 아닙니다.
3. 등록 후 개요의 **애플리케이션(클라이언트) ID**를 복사합니다. ‘개체 ID’나 ‘디렉터리 ID’가 아닙니다.
4. 인증 → 고급 설정에서 **공용 클라이언트 흐름 허용**을 켭니다. Device code 흐름을 사용하므로 웹 리디렉션 주소와 클라이언트 비밀 키는 필요하지 않습니다.
5. API 사용 권한 → Microsoft Graph → 위임된 권한에 `Files.ReadWrite.AppFolder`, `offline_access`를 추가합니다. 이 앱에 필요하지 않은 권한은 추가하지 않습니다.
6. ID를 폰 앱에 입력하고 OneDrive 로그인 버튼을 누릅니다. 표시된 코드를 Microsoft 로그인 페이지에 입력하고 사진을 저장할 **개인 OneDrive 계정**으로 동의합니다.

앱은 `offline_access Files.ReadWrite.AppFolder`를 요청합니다. 토큰은 폰의 Android Keystore로 암호화해 저장합니다. OneDrive 저장 폴더는 Microsoft가 앱용으로 지정하는 `Apps/<등록 앱 이름>/KakaoIntake/`입니다. 화면 언어에 따라 `Apps`는 다르게 표시될 수 있습니다. 기존 관리허브 업무자료 폴더에 바로 쓰는 방식은 아닙니다.

## 2. 앱 설치·권한

개발용 APK를 설치합니다. 최초 설치에는 USB를 사용해도 상시 수집에는 필요하지 않습니다.

```powershell
.\adb.exe install -r "C:\실제경로\ian-kakao-collector-debug.apk"
```

- 앱에서 클라이언트 ID와 수집 방 이름을 한 줄에 하나씩 입력하고 설정 저장을 누릅니다.
- OneDrive 로그인을 마칩니다.
- ‘사진·알림 권한 허용’에서 **모든 사진 허용**을 선택합니다. 일부 사진만 허용하면 새 카카오톡 사진을 읽지 못할 수 있습니다.
- 접근성 → 설치된 앱 → 이안 카카오 수집을 켭니다. One UI에서 제한된 설정이라고 나오면 앱 정보의 메뉴에서 ‘제한된 설정 허용’ 가능 여부를 확인합니다. 회사 정책이 막으면 관리자 설정이 필요합니다.
- 알림 접근 → 이안 카카오 수집을 켭니다. 카카오톡에서도 해당 방의 메시지 알림을 켭니다.
- 앱 배터리는 제한 없음으로 설정하고 절전/초절전 대상에서 제외합니다.
- 벽면 충전기에 연결합니다. 개발자 옵션의 **충전 중 화면 켜짐 유지**를 사용할 수 있습니다. USB 데이터 연결은 필요하지 않습니다. 자동 잠금과 화면 꺼짐으로 수집이 중단될 수 있습니다.
- ‘수집 시작’ 후 테스트 방에 사진을 받습니다. 수동 점검은 ‘현재 열린 방 사진 수집’에서 방을 선택하고 해당 방으로 이동합니다. 앱은 제목 일치 확인 후에만 사진을 조작합니다.

사진 저장 중 뷰어의 창·화면 구성이 바뀌거나 저장 후 원래 허용된 방으로 돌아오지 못하면 업로드하지 않고 중단합니다. 이 보호 동작도 실기기에서 확인해야 합니다.

자동 방 열기가 One UI에서 차단되거나 방 제목 ID가 맞지 않으면 수집이 중단됩니다. 이 경우 고정 좌표로 강행하지 말고 해당 단말의 화면 요소를 확인해 수정해야 합니다.

## 3. 저장 결과

```text
Apps/<앱 이름>/KakaoIntake/<receiptId>/
  photo-01.jpg
  photo-02.jpg
  receipt.json
```

사진 업로드가 끝난 뒤 `receipt.json`을 마지막에 올립니다. JSON에는 사진 개수·크기·SHA-256·관찰 시각·방 이름·알림 정보·주변 화면 대화가 있습니다. `attribution`은 정확한 개별 사진 발신자 연결이 아니라 화면 문맥임을 표시합니다. 주변 대화에 개인정보가 포함될 수 있으므로 수집 대상 방과 저장 계정의 접근 범위를 업무용으로 제한하세요.

전송 실패 시 앱 상태에 오류를 표시하고 내부 대기 파일을 유지합니다. 업로드 완료 후 앱 내부 사진 사본만 정리하며 카카오톡이 저장한 사진은 지우지 않습니다. 앱 삭제·앱 데이터 초기화는 미전송 사진도 삭제하므로 대기 0건을 확인하기 전에는 하지 마세요. 완료 후 폰에 남는 카카오톡 저장 사진과 접수 이력의 보관 기간은 운영 중 별도로 관리해야 합니다.

## 4. 실기기 합격 기준

1. 테스트 방에 새 단일 사진을 보내고 OneDrive 파일이 열리는지 확인합니다.
2. 새 묶음사진 세 장을 보내고 파일 세 개와 JSON의 개수·해시를 확인합니다.
3. 네트워크를 끊고 수집한 뒤 재연결 시 대기 건이 업로드되는지 확인합니다.
4. 수집 중지 후 새 사진이 수집되지 않는지 확인합니다.
5. 등록하지 않은 방은 열거나 수집하지 않는지 확인합니다.
6. 앱을 재시작하고 수집 시작 후 기존 대기 파일이 복구되는지 확인합니다.
7. 화면 잠금·권한 해제·배터리 제한 시 중단 상태를 확인합니다.

이 검증을 마치기 전에는 퇴사자 업무를 완전히 대체하는 무인 수집기로 사용하지 않습니다. 현재 실제 단말에서는 ADB 사진 저장·파일 반출만 확인됐고 이 APK의 OneDrive 로그인·직접 업로드는 아직 검증되지 않았습니다.

## 빌드

JDK 17, Android SDK 35, Build Tools 34.0.0, Gradle 8.10.2를 사용합니다. Android Studio에서 이 폴더를 열거나 다음처럼 빌드합니다.

```bash
gradle --no-daemon assembleDebug lintDebug
```

출력: `app/build/outputs/apk/debug/app-debug.apk`. 개발용 서명이며 배포 키는 저장소에 넣지 않습니다. Gradle wrapper가 포함되어 있으므로 `./gradlew` 또는 Windows의 `gradlew.bat`를 사용할 수 있습니다.
