# 이안 문자 사진 저장 v0.3.1

특정 번호에서 이미 받은 사진을 시작일~종료일로 지정해 **전체 목록 조회 → 기간 대상 확정 → 한 장씩 OneDrive 전송 → 앱 임시 사본 정리**하는 독립 Android 앱입니다. 기존 카카오 앱/웹/DB를 변경하지 않습니다. 원본 문자와 RCS 첨부는 보존합니다.

## 왜 저장 방식을 바꿨나

v0.2.x는 삼성 메시지에서 저장을 누른 뒤 MediaStore에서 새 Download 파일을 찾았습니다. 실제 단말은 JPEG/Download/소유 앱/미디어 등록이 정상인데도 단계4에서 멈췄습니다. 이미 저장됐거나 사진을 여는 중 생성된 파일은 신규 파일 차이만으로 안정적으로 연결할 수 없습니다.

v0.3.0은 **삼성 공유가 전달한 원본 content URI**를 읽습니다. 새 Download 파일을 만들거나 파일명 날짜를 추측하지 않습니다. 이미 받은/이미 저장된 사진도 같은 원본 전달 흐름을 사용합니다. 한 장 저장 버튼을 대신 누르는 기능이 아닙니다.

## 설치와 사용

기존 문자 앱을 삭제하거나 데이터를 초기화하지 마세요. 같은 서명의 업데이트입니다.

```powershell
.\adb.exe install -r ".\ian-mms-collector-v0.3.1-debug.apk"
```

1. **이안 문자 사진 저장**을 엽니다. 기존 OneDrive 로그인·번호·기간은 유지합니다. 처음 설치라면 기존 공개 Microsoft 클라이언트 ID로 로그인합니다. 개인 OneDrive와 `Files.ReadWrite`, `offline_access`를 사용하며 새 Entra 등록/비밀 키는 필요하지 않습니다.
2. **화면 방식: 접근성 설정**에서 이 앱을 켭니다. 업데이트 후 필요하면 연결 상태를 확인합니다. 새 방식은 항목별 URI 권한을 사용하므로 새 사진 전체 접근/갤러리 관리 권한은 필요하지 않습니다. 호출 앱의 OS 신원을 확인하기 위해 **Android 15 이상**이 필요합니다. Jump3/One UI8 단말을 기준으로 개발했습니다.
3. 번호와 시작일·종료일을 선택하고 **기간 전체 사진 수집 시작**을 누릅니다. 해당 대화 사진이 모두 상대방에게 받은 것임을 확인합니다. 보낸 사진이 섞인 대화는 아직 지원하지 않습니다.
4. 지정 번호 대화를 직접 여는 intent를 실행하고, 헤더 번호를 확인한 뒤 공유 첨부 메뉴를 찾습니다. 삼성 UI 정책상 직접 열기/메뉴 탐색이 안 되면 해당 대화를 열어두거나 사진 한 장을 전체 화면으로 열어 연결할 수 있습니다. 그 사진을 무조건 저장하지는 않습니다.
5. 첨부 목록 전체를 먼저 순회해 기간 내 후보 N장을 확정합니다. 다시 처음으로 돌아와 대상별 번호·날짜를 재검증하고 **공유 → 이안 사진 원본 전달**을 선택합니다. 시스템 공유 화면에서 자동 선택을 못 하면 이 항목을 직접 선택할 수 있습니다. 처음 이후에도 수동 선택이 반복된다면 자동화가 완료된 상태가 아니므로 해당 화면/상태를 확인해야 합니다.
6. 앱이 전달 URI를 앱 전용 큐에 복사하고, OneDrive 업로드를 확인한 뒤 앱 임시 사본을 제거합니다. 다음 사진으로 반복합니다. 완료는 전체 계획 항목과 전송/기존/정리 건수가 맞을 때만 표시합니다. 화면을 켜고 잠금을 해제한 채 다른 조작을 하지 마세요.

저장 위치: `이안카카오/문자/발신번호/표시날짜_시간_<접수UUID>_01.jpg` 등. 사진 원본 바이트를 유지하며 JSON/TXT는 원격에 올리지 않습니다. 사진당10MB, JPG/PNG/WEBP/GIF를 지원합니다.

## 날짜·중복·실패

한국 시간 기준 시작일/종료일을 모두 포함합니다. 삼성 표시 날짜에 연도가 없으므로 화면 방식은 올해 안의 기간만 허용하며, 다른 연도가 명시된 사진은 제외합니다. 화면 시각이 분 단위여서 파일명 초/밀리초는0입니다. 파일명 안의 날짜를 수신 날짜로 사용하지 않습니다.

날짜·사진 바이트 해시·동일 시각/바이트의 등장 순번으로 안정 접수 ID를 만듭니다. 같은 분에 동일 사진이 두 장 있어도 각각 보존하고, 동일 기간 재실행은 같은 ID로 재시도합니다. 기존 업로드도 원격 파일 존재/계정/크기를 다시 확인합니다. 이전 v0.2.x 또는 MMS 직접 조회 결과와 상호 중복 제거는 보장하지 않습니다.

전송 실패는 앱 임시 사진을 유지합니다. 같은 번호/기간으로 다시 실행하면 재시도합니다. 네트워크 중지 요청은 현재 응답을 되돌리지는 않지만 다음 사진으로 진행하지 않습니다. URI 원본 읽기는30초 제한/중지 확인을 두며, 제공자가 취소·닫기를 무시하면 새 읽기를 막고 앱 강제 중지를 안내합니다. 늦게 끝난 읽기가 새 작업에 사진을 등록하지 않도록 분리했습니다.

강제 종료로 receipt 작성 전 중단된 앱 임시 디렉터리는 별도로 보존하고 재접수할 수 있습니다. 이 미완성 보존본은 정상 완료 사본과 다르며 자동 삭제하지 않을 수 있습니다. 앱 삭제/데이터 초기화는 미전송 사본도 지우므로 대기 건수를 먼저 확인하세요.

## 삭제 범위

**공유받아 만든 앱 전용 임시 복사본만 업로드 확인 후 정리합니다.** 새 Download 사진을 만들지 않으므로 갤러리 사본 삭제 권한도 새 흐름에 필요하지 않습니다. 원본 문자/RCS 첨부, 사용자 기존 갤러리 파일, 과거 실패 때 남은 Download 파일은 추측 삭제하지 않습니다. v0.2.x의 이미 기록된 레거시 접수는 앱 전용 큐만 재전송·정리하며, 갤러리 삭제는 더 이상 실행하지 않습니다. 광범위 미디어 읽기/사진 관리 권한도 제거했습니다.

## 권한과 원본 전달 확인

접근성 범위는 삼성 메시지, 허용된 시스템 공유 UI, 이 앱입니다. 공유 Activity는 진행 중인 단일 사진 요청에서만 파일을 읽으며, OS ComponentCaller로 실제 호출 패키지와 URI 읽기 권한을 확인합니다. 호출 패키지명만 믿지 않고 preinstalled/updated system 여부와 원본 제공자 system 여부도 확인합니다. 한 개의 content URI만 허용하고 ClipData/EXTRA_STREAM이 다르면 거절합니다. 일반 외부 앱에서 임의 사진을 보내도 조용히 업로드하지 않습니다.

기존 **일반 MMS 기간 조회**는 별도 경로로 남아 있으며 Android13+ READ_SMS 제한 권한을 사용합니다. 채팅+(RCS) 사진은 이 provider에 없을 수 있습니다. 문자 보내기/원본 삭제/기본 문자 앱 변경 권한은 추가하지 않습니다.

## 검증 구분

실제 단말 확인: 공유 첨부54개, 번호/날짜/저장/앨범 요소, 저장 버튼 실행, Download JPEG 생성과 정상 MediaStore 메타데이터. 이것은 새 URI 공유 배치의 실기기 성공 증거가 아닙니다.

모의 통합: 제공된28개 실제 목록 XML과26개 더 오래된 가상 항목으로 전체 목록을 먼저 확인한 뒤 기간 내19개만 처리했습니다. 실제 MmsScreenAccess/MmsShareFiles/OneDrive 코드를 연결해 URI 원본19개 → 모의 Graph19개 전송 → 앱 임시19개 제거를 확인했습니다. 처음 열었던 사진/기간 밖 항목/Save 버튼/MediaStore 신규파일 검색은 사용하지 않았습니다. 실제 원격 OneDrive 전송으로 보고하지 않습니다.

추가 임시 검사: 양끝 날짜, 다중 페이지, 동시각 중복, 기간 밖 제외, 직접 대화 헤더→메뉴 탐색, 미완료/불명 위치 중단, URI 원본/재시도/원본 보존, spoof 패키지명 거부, provider 정지 중 취소/오래된 읽기 격리, 기존 서비스/MMS/Graph 회귀. 저장소에는 테스트 파일을 추가하지 않았습니다.

남은 실기기 검증: 대화 직접 열기와 메뉴 구조, 시스템 공유 대상 자동 선택, OS caller/provider 권한 확인, 공유 후 뷰어 복귀, 전체19장 실제 OneDrive 파일 열기·임시 사본 정리, 화면 유지/중지/재시도. 이 검증 전에는 무누락 무인 운영 완료라고 하지 않습니다.

빌드: `android/kakao-collector`에서 `./gradlew :mms:assembleDebug :mms:lintDebug`. Store/Rules/OneDrive는 기존 app 소스에서 build 디렉터리로만 Sync해 재사용합니다. 서명키는 저장소에 커밋하지 않습니다.

## v0.3.1 공유창 수정

실제 단말의 시스템 공유창 `com.android.intentresolver`를 조회할 수 있도록 명시적인 패키지 가시성을 등록했습니다. 시스템 앱 여부 검사는 유지합니다. 더보기에서 수신 항목 이름 대신 앱 이름으로 표시되어도 설치된 자체 수신 구성요소의 정확한 이름과 대조해 선택합니다. 같은 이름의 외부 공유 대상이 있으면 중단합니다. 공유창 전환 중에는 최대5초 동안 읽기만 하며 기다립니다.

임시 모의 검사에서 패키지 가시성, 앱 이름 선택, 중복 이름 거부, 기간 경계·번호·목록 탐색 회귀를 통과했고 Android 빌드와 lint를 통과했습니다. 실제 폰의 자동 공유 대상 선택부터 전체 기간 업로드까지는 업데이트 후 확인이 필요합니다.
