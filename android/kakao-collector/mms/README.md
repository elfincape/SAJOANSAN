# 이안 문자 사진 저장

삼성 메시지의 **일반 MMS 수신 사진**을 지정 번호·시작일·종료일로 조회해 OneDrive에 저장하는 별도 Android 앱입니다. 기존 카카오 수집 앱은 유지합니다. Android 13 이상이며 실제 법인폰 검증이 필요한 개발용 버전입니다.

## 설치와 최초 설정

APK를 PC의 platform-tools 폴더에 넣고 PowerShell에서 실행합니다.

```powershell
.\adb.exe install -r ".\ian-mms-collector-v0.1.0-debug.apk"
```

1. 폰에서 **이안 문자 사진 저장** 앱을 엽니다. 카카오 수집 앱과 다른 앱입니다.
2. **1. OneDrive 로그인** → 표시된 코드를 브라우저에 입력 → 앱으로 돌아와 ‘OneDrive 로그인 완료’를 확인합니다. 기존 Microsoft 공개 클라이언트 ID가 입력되어 있습니다. Entra 앱을 새로 등록하거나 비밀 키를 만들 필요가 없습니다. 기존 앱에 설정한 개인 OneDrive 계정과 위임된 `Files.ReadWrite`, `offline_access`를 사용합니다.
3. **2. 문자 읽기·알림 권한 허용**에서 권한을 허용합니다. Android의 문자 읽기 권한은 번호별 권한이 아니지만 앱은 지정 번호의 수신 MMS 이미지만 업로드합니다. 일반 MMS 방식은 문자 보내기·삭제나 기본 문자 앱 변경을 요청하지 않습니다. v0.2.0의 선택적 화면 방식 권한은 아래 별도 항목을 따릅니다.
4. 발신번호와 시작일·종료일을 선택하고 **지정 기간 사진 저장**을 누릅니다. 초기 번호는 요청한 번호로 입력되어 있으며 변경할 수 있습니다.

READ_SMS는 제한 권한이므로 설치 프로그램/단말 정책이 허용하지 않으면 동작하지 않습니다. 권한 항목이 없거나 계속 거부되면 오류 문구를 확인해야 합니다. 권한을 허용하지 않은 채 정상 수집으로 처리하지 않습니다. 이 경우 RCS 화면 자동화로 임의 전환하지 않습니다.

이 앱은 새 패키지 `kr.ianlogistics.mmscollector`를 사용합니다. 기존 카카오 APK의 서명키가 현재 환경에 없어 덮어쓰기 대신 독립 앱으로 제공하며, 기존 카카오 앱과 로그인·큐는 보존합니다. 새 앱에서 OneDrive 로그인은 한 번 필요합니다. 새 문자 앱의 이후 업데이트는 같은 서명을 사용해야 합니다. 서명키는 저장소에 커밋하지 않습니다.

## 날짜와 저장 방식

- 날짜는 **한국 시간(Asia/Seoul)** 기준이며 시작일 00:00부터 종료일 다음날 00:00 직전까지 포함합니다. 폰 시간대를 변경해도 이 기준은 유지합니다.
- MMS 수신함의 날짜와 FROM 주소를 사용합니다. `+82`/`0082`와 국내 번호·하이픈을 정규화하고 전체 번호를 비교합니다. 보낸 문자나 번호 뒷자리만 일치하는 문자는 수집하지 않습니다.
- `이안카카오/문자/발신번호/수신날짜_시간_<접수UUID>_01.jpg` 등으로 저장합니다. 파일명 날짜는 이번 내보내기 실행 시각이 아니라 MMS의 날짜입니다.
- JPG·PNG·WEBP·GIF 원본 바이트를 보존하며 사진당 10MB, MMS당 30장까지 지원합니다. 원격 JSON·TXT, AI 분석과 업무 생성은 추가하지 않습니다.
- 같은 MMS·첨부·OneDrive 계정은 같은 접수 ID를 사용합니다. 겹치는 기간을 다시 실행하면 이미 전송한 건을 건너뛰며, 실패 중인 건은 같은 파일명으로 재시도합니다.
- 업로드를 확인한 앱 내부 사본만 정리합니다. **원본 문자, MMS 첨부, 기존 갤러리 사진은 삭제하지 않습니다.** 앱 데이터 삭제/앱 제거는 미전송 사본도 지우므로 전송 대기를 먼저 확인하세요.

## 진행·오류

진행 알림과 앱 상태에 전송 장수, 기존 접수 건수, 사진 없음/미다운로드 건수, 실패 건수를 표시합니다. 조회 결과 0건은 정상 저장을 뜻하지 않습니다. 번호·기간, 일반 MMS인지, 삼성 메시지에서 사진 다운로드가 완료되었는지 확인하세요. 채팅+(RCS)와 삼성 전용 비공개 메시지는 지원을 보장하지 않습니다.

네트워크 오류는 접수를 큐에 보존합니다. 연결 복구 후 같은 번호와 기간으로 다시 실행하면 먼저 해당 조건의 대기 건을 재시도합니다. 다른 번호·기간의 대기 건은 자동 전송하지 않습니다. 저장 중지는 다음 사진 전송을 막지만 이미 전송 중인 네트워크 요청의 결과를 되돌리지는 않습니다. 이전 작업이 정리될 때까지 재실행을 막습니다.

수집은 사용자가 버튼을 눌렀을 때 실행하며 새 문자 상시 감시 기능은 아닙니다. 화면 조작 없이 provider를 읽는 구조이지만 실제 One UI에서 화면 꺼짐·절전 상태의 완료를 확인한 것은 아닙니다. 권한·배터리 정책·프로세스 종료가 영향을 줍니다. 재부팅 후 자동 실행은 하지 않습니다. 강제 프로세스 종료 시 미완성 staging 사본이 앱 전용 공간에 남을 수 있습니다.

## 검증 현황

임시 Java 검사로 날짜 경계/윤일/역전, 번호 정규화, 이미지 헤더, 안정 ID, 모의 MMS provider 필터/빈 조회/권한 거부/취소/재시도, 모의 Graph의 원본 바이트/폴더/실패 큐/중지 분리, 서비스 재실행 경합을 확인했습니다. 새 모듈과 기존 카카오 모듈 Android build/lint, 기존 웹 build를 수행했습니다. 저장소에는 테스트 파일을 추가하지 않았습니다. 네이티브 앱이므로 웹 브라우저 검사로 실제 폰 UI를 검증했다고 보고하지 않습니다.

실제 법인폰에서 다음 확인이 남아 있습니다.

1. 문자 읽기 권한이 허용되고 이미 내려받은 MMS 사진을 읽는지 확인합니다.
2. 시작일·종료일의 사진이 모두 포함되고 다른 번호/기간 사진은 제외되는지 확인합니다.
3. OneDrive 사진을 열어 실제 이미지임을 확인하고 원본 문자가 남는지 확인합니다.
4. 같은 기간 재실행 시 중복이 없는지, 네트워크 실패 후 재시도로 전송되는지 확인합니다.
5. 화면 꺼짐·절전·중지 후 재실행을 단말에서 확인합니다.

빌드: 저장소의 `android/kakao-collector`에서 `./gradlew :mms:assembleDebug :mms:lintDebug`. 출력은 `mms/build/outputs/apk/debug/mms-debug.apk`입니다. Store/Rules/OneDrive 원본은 Gradle Sync 작업으로 기존 app 소스에서 빌드 폴더로만 가져옵니다.

## v0.2.0 삼성 메시지 화면 방식

일반 MMS 조회가 0건인 파일전송 사진을 위해 **삼성 메시지 화면으로 기간 저장**을 추가했습니다. 원래의 일반 MMS 조회도 유지합니다. 기존 문자 앱을 삭제하지 않고 같은 서명의 새 APK를 덮어 설치합니다.

```powershell
.\adb.exe install -r ".\ian-mms-collector-v0.2.0-debug.apk"
```

1. 앱의 **화면 방식: 사진·알림 권한 허용**에서 **모든 사진**을 허용합니다. 기존 OneDrive 로그인은 유지됩니다.
2. **화면 방식: 접근성 설정**에서 **이안 문자 사진 저장**을 켭니다. 삼성 메시지 패키지만 조회·조작하며 일반 MMS 방식에는 필요하지 않습니다. One UI에서 제한된 설정이라면 앱 정보의 제한된 설정 허용 가능 여부를 확인합니다.
3. 전송 후 새 Download 저장본을 삭제하려면 **화면 방식: 전송 후 저장본 삭제 권한**도 허용합니다. 권한이 없으면 전송은 하고 저장본은 유지합니다. 원본 문자와 RCS 첨부는 삭제하지 않습니다.
4. 번호와 올해 안의 시작일·종료일을 선택하고 **삼성 메시지 화면으로 기간 저장**을 누릅니다. 대화의 첨부 사진이 모두 상대방에게 받은 사진임을 확인해야 합니다. 보낸 사진이 섞인 대화는 현재 화면 방식으로 처리하지 않습니다.
5. 시작 후 60초 안에 삼성 메시지에서 해당 번호와의 대화에 있는 **사진 한 장을 전체 화면으로 엽니다**. 공유 첨부 목록 화면 자체에서 시작하지 않습니다. 앱이 번호를 확인한 사진 뷰어에서 목록으로 이동합니다. 화면을 직접 잠그거나 다른 조작을 하지 마세요.

날짜는 `viewer_sub_title`의 표시를 사용합니다. 예: `9월 17일, 오후 6:37`. **연도가 생략된 날짜는 현재 한국 시간 연도**로 해석하므로 화면 방식은 올해 안의 기간만 허용합니다. 다른 연도가 명시된 사진은 제외합니다. 파일명 날짜를 수신 날짜로 사용하지 않습니다. 화면에는 초가 없어 파일명 초·밀리초는 0이며 분 단위 표시 시각입니다. 같은 번호·표시 시각·사진 해시는 같은 접수로 취급합니다. MMS 직접 조회와 화면 방식 사이의 상호 중복 제거까지 보장하지는 않습니다.

목록 처음/끝은 RecyclerView의 전체 행과 사진 행·열 위치로 확인합니다. 위치 정보가 없거나 이동 요청이 중간에서 거부되면 나머지를 성공으로 표시하지 않고 미완료로 중단합니다. 목록의 수가 바뀌거나 번호·날짜가 달라지거나, 날짜 형식을 읽지 못하면 중단합니다.

화면 방식은 새로 생긴 **삼성 메시지 소유의 Download 이미지**만 읽습니다. 기존 ID, 수집 전에 삽입된 미완료 다운로드의 generation, 미디어 DB 재생성을 확인해 기존/다른 파일로 오인하지 않도록 검사합니다. 동시에 여러 저장 파일이 생기면 연결을 중단합니다. 다른 조작이나 동시 삼성 메시지 다운로드를 피하세요. 하나의 UI 저장과 비동기 미디어 파일 생성을 원자적으로 연결하는 공식 API는 아니므로 무누락·완벽한 연결을 보장하는 방식은 아닙니다.

OneDrive 업로드 후 계정·원격 파일 존재·크기(서버 해시가 있으면 해시), 새 저장본의 ID·생성 generation·경로·소유 앱·서명·바이트 해시를 다시 확인합니다. 사진 관리 권한이 있을 때만 시스템 삭제를 요청하며 상태 문구도 ‘삭제 요청’으로 표시합니다. 비동기 요청과 검사 사이 파일 편집을 원자적으로 막지는 못하므로 처리 중 저장본을 편집하지 마세요. 이전부터 있던 사진을 폴더 단위로 삭제하지 않습니다.

사용자가 중지를 누르면 진행 중인 네트워크 응답이 끝날 때까지 새 실행을 막고 그 다음 사진을 처리하지 않습니다. 실패한 앱 내부 접수는 유지되며 같은 번호·기간의 화면 방식을 다시 실행하면 먼저 재시도합니다. 화면 모드는 최대 20분 화면 켜짐 잠금을 사용하지만 사용자 잠금 해제를 대신하지 않습니다. 손으로 잠그면 중단합니다. 실제 단말의 절전·잠금·접근성 정책에 따라 영향받을 수 있습니다.

### 검증 구분

- 실제 단말에서 사용자 확인: 공유 첨부 54개 목록, 번호/날짜 뷰어 요소, 저장 버튼, `/sdcard/Download/`에 JPEG 파일 생성.
- 모의 검증: 날짜 규칙, 실제 화면 상태기계의 여러 장/다음 페이지 처리, 같은 분 사진, 번호 불일치, 위치·스크롤 실패, 알 수 없는 설명 중단, 기존/미완료 파일 제외, DB 재생성, 원본 바이트, 업로드 후 변경되지 않은 새 저장본만 삭제 요청, 기존 MMS/서비스/Graph 회귀.
- 미검증: 새 APK에서 삼성 RecyclerView 위치 제공 여부, MediaStore 소유 앱·generation 조회 권한, 전체 자동 저장→OneDrive→갤러리 사본 삭제, 실제 화면 유지와 설정 UI. 앱은 이 정보를 얻지 못하면 추측으로 진행하지 않고 상태에 미완료 원인을 표시합니다.

## v0.2.1 사진 뷰어 인식 진단

사용자 단말의 ‘화면 단계 0 시간 초과’는 사진 번호 확인 전에 대기 종료된 상태입니다. 실제 단말의 정확한 원인은 아직 확인되지 않았습니다. 다음 호환·진단 동작을 추가했습니다.

- 삼성 사진 뷰어의 이미지 요소는 있으나 번호/날짜 도구 모음이 숨겨졌으면 사진을 눌러 표시를 요청합니다. 단계당 최대 두 번이며 시간 제한을 연장하지 않습니다. 번호·날짜 확인 전에는 저장 버튼을 누르지 않습니다.
- 정확한 번호/날짜 ID의 text가 비어 있고 content-desc에 값이 있으면 그 값을 사용합니다. 번호 비교·날짜 검증은 그대로 유지합니다.
- 대기 중 현재 앱 패키지, 읽은 삼성 요소 수, 사진/번호/날짜/앨범 존재와 번호 일치 여부를 표시합니다. 메시지 본문, 실제 날짜·번호 값은 진단에 기록하지 않습니다. 앱으로 돌아와도 최근 삼성 화면 진단을 보존하며 시간 초과에 포함합니다.
- 번호/날짜 요소가 보이지만 text/설명 값이 모두 빈 경우에는 버튼 표시를 강행하지 않고 안전하게 대기/중단할 수 있습니다.
