# 기존 웹 UI·UX 개선 실행 구상 — 8단계

기준: 2026-11-13, main `d16aca5024401227e54fb25a6c5d33ae91b9178a`.
근거: [웹 전반 점검·18개 발견 사항·35개 화면 적용표](../reviews/WEB-UX-AUDIT-2026-11-13.md).
상태: **8/8 완료 / 구현·격리 검증·운영 배포·공개 경로 확인 완료**. 사용자 후속 지시 “멈춤없이 마지막까지 작업”에 따라 전체 단계를 연속 실행했다. [단계별 결과·35개 화면 적용 범위·미확인 항목](../handoffs/WEB-UX-IMPLEMENTATION-RESULT.md)을 기준으로 한다. 기존 구조 개선 7단계와 별도다.

## 목표와 선택한 방향
사용자가 목록을 읽고, 연결 원본을 확인하고, 한 필드를 저장하는 동안 웹 전체가 멈추는 느낌을 줄인다. 작업이 성공했는지, 어디까지 저장됐는지, 실패하면 무엇부터 다시 하면 되는지 짧고 일관되게 보여준다.

검토한 방향:
1. 로딩 문구/스피너만 감춘다: 실제 대기·잠금·파일 소실은 그대로이므로 제외.
2. **기존 인증/셸/편집기/저장 계약을 유지하면서 대기·잠금·복귀 단위를 바로잡는다: 권장.** 가장 자주 쓰는 공통 경로부터 체감 개선, 기존 데이터/업무 의미 보존.
3. 새 ERP/라우터/디자인 시스템으로 다시 만든다: 이미 확정한 기존 웹 사용 방향과 충돌하고 이관/재검증 비용이 커 제외.

이는 조사에 근거한 권장 구상이며 사용자가 새 기능이나 권한 정책을 확정했다는 뜻은 아니다. 통상적인 구현 선택은 다음 작업자가 판단하되 새 플랫폼·업무 의미 변경은 하지 않는다.

## 모든 단계에 적용할 원칙
- 기존 DB·RLS·원본 ID·원본/연결 조건·CAS/충돌·멱등·입력 검증을 유지한다. 권한 확인을 삭제하거나 무기한 캐시하지 않는다.
- 최초 로그인/세션 상실/현재 자료에 대한 접근 불가는 명확히 처리한다. 이미 인증된 정상 이동마다 새 로그인 화면을 띄우는 것과 구분한다.
- 목록은 가능한 한 남겨두고, 불러오는 부분만 상태를 표시한다. 기존 값을 최신으로 오해하지 않도록 갱신 실패/이전 조회 상태를 구분한다.
- 작은 저장은 그 저장 위치에서 표시한다. 전체 화면 덮개나 무관한 버튼 비활성으로 대신하지 않는다. 실제 성공 전 ‘저장됨’ 표시 금지.
- 저장 중 이탈/중복 제출 방지는 유지한다. 저장 중 상태를 안전하게 다른 화면에 넘길 수 없는 경로는 해당 이탈만 설명과 함께 막는다. 무조건 비동기 백그라운드 저장으로 바꾸지 않는다.
- 기존 테마·데스크톱 밀도·패키지를 유지한다. 장식 카드/설명/애니메이션을 추가하지 않는다. 모바일은 기본 깨짐만 확인한다.
- File 바이트·서버 저장·브라우저 초안·다운로드 결과를 구분한다. 미보존 파일은 재선택이 필요하다고 정확히 알린다. 브라우저 종료 후 계산 지속을 약속하지 않는다.
- 폐기한 Notion은 현재 탐색에서 정리한다. 과거 보고서/자료를 지우거나 OneDrive/OneNote를 폐기하지 않는다.
- 각 단계는 담당 화면·제외 화면·검증 방법·운영 반영을 따로 기록한다. 대표 화면 1개 통과로 전체 웹 완료라고 쓰지 않는다.

## 1/8 — 인증·이동
수정 후보: `app/src/lib/auth.ts`, `main.tsx`, `lib/workspace-navigation.ts`, `components/AdminPage.tsx`.

- 유효한 기존 인증 컨텍스트와 동시 조회 합치기를 사용한다. 매 이동의 `loadAuthContext(true)` 제거 방향. 현재 30초 유효성 기준을 먼저 재사용하고, 시간을 늘리는 것을 해결책으로 삼지 않는다.
- 로그아웃/사용자 변경/비활성/권한 변경/세션 만료 시 무효화 및 서버 거절은 유지한다. 다른 사용자의 캐시나 화면 상태가 섞이지 않아야 한다.
- 내부 이동 중 전체 body inert 대신 새 이동 요청/변경 충돌만 제어한다. 빠른 연속 선택은 마지막 목적지에 도착하고 늦은 응답이 되돌리지 않게 한다.
- 공통 셸을 매 페이지의 로딩 상태와 분리한다. 권한 미확정 상태에서 새 민감 데이터나 수정 기능을 노출하지 않으며, 읽을 수 있던 현재 화면을 보존할 수 있는 상태와 세션 만료를 구분한다.
- 연속 이동 제외 목록부터 정리한다. 기사는 OneDrive/파일 URL/정리 이벤트가 있어 빠져 있으므로 생명주기를 확인한 뒤 편입한다. 파일 도구는 3단계에서 작업 보존 후 편입 여부를 결정한다.
- 검증: 최초 로그인/직접 URL, 유효 캐시의 3회 연속 이동, 만료·비활성·권한 축소·다른 계정, 뒤로/앞으로, 지연/실패/연속 클릭. 네트워크 호출 수와 화면 잠금 여부를 따로 기록한다. 성공한 과거 전체 검사 반복은 하지 않는다.

## 2/8 — 저장 표시·잠금
수정 후보: `EditorStatus.tsx`, `WorkspaceFrame.tsx`, `DashboardCellEditor.tsx`, 원본 폼, `portal/PortalShell.tsx`와 Portal의 실제 busy 전달 부분.

- `controlsDisabled`의 하나짜리 전역 busy를 삭제부터 하지 말고 호출자별 의미를 분류한다: 자료 조회, 저장, 업로드, 분석, 삭제, 화면 전환.
- 저장 대상 입력/재제출/동일 대상 삭제만 잠그는 최소 범위부터 적용한다. 저장과 관계없는 테마·목록 읽기·복사·메뉴 펼침은 유지한다.
- 표시 계약: 미저장→저장 중→저장됨. 실패는 입력 유지+재시도, 충돌은 최신값 비교+명시적 재적용, 응답 유실은 결과 확인 필요. 성공 토스트와 상태 띠를 중복 강조하지 않는다.
- 짧은 조회에 스피너를 즉시 깜박이지 않는다. 긴 작업은 실제 진행 단계와 경과 상태를 보인다. ‘취소’는 실제 중단 가능한 작업에만 제공한다.
- 검증: 한 필드 저장, 중복 클릭, 저장 중 새 입력, 네트워크 실패/응답 유실/충돌, 저장 중 이탈. 후기 응답으로 새 입력을 덮어쓰지 않는다. 서버 저장이 확인된 상태만 성공 처리한다.

## 3/8 — 작업 문맥·파일
수정 후보: 기존 목록/초안 저장 모듈, Workbench, Drivers/Vehicles/Companies, ExcelCompare/PdfTools/ImageStraightener/DispatchParser/Transfers의 상태 수명.

- 기존 사용자·동일 탭·화면/원본 ID별 보존 방식을 재사용한다. 필터/정렬/행/스크롤/우측 패널/조건을 분리한다.
- Excel 파일 선택→허브→복귀 재현부터 해결한다. 살아 있는 탭의 File 수명과 문서 전체 새로고침 이후 재선택을 구분한다. 큰 파일 바이트를 sessionStorage에 넣지 않는다.
- 입력을 잃을 수 있는 경우만 이탈을 알린다. 내용이 없는 폼/이미 저장한 상태에서 반복 확인하지 않는다.
- 파일 이름·지문·시트/조건이 복원돼도 바이트가 없으면 ‘원본 재선택 필요’. 저장된 결과가 있다면 재계산하지 않고 기존 결과 열기 제공.
- 검증: 같은 탭 이동/복귀/새로고침, 다른 사용자/원본/센터의 분리, 파일 재선택 불일치, 저장 실패 입력 유지. 서버 초안/PC 간 동기화/범용 IndexedDB 파일 보관 플랫폼은 만들지 않는다.

## 4/8 — 연결 상세와 편집 규칙
수정 후보: 기존 LinkedRecordDetail, DashboardDetail, Workbench, Routes/RouteEdit/원본 목록, PortalRecordDetail의 사용처.

- 이름/식별값 클릭은 해당 원본 확인. 값의 빠른 수정은 명시적 편집/F2, 연결 교체·순서·inherit/set/clear는 별도 연결 편집.
- 원본을 조회하는데 전체 배경을 잠그는 중첩 모달이 필요한지 사용처별로 줄인다. 원본 수정/삭제 확인처럼 주의가 필요한 경우의 포커스/이탈 가드는 유지한다.
- iframe 재인증과 닫기 전체 재조회는 1단계 계약에 맞춰 대기 범위를 줄인다. 즉시 iframe을 모두 폐기하거나 새 상세 엔진을 만들지 않는다.
- 원본 수정 후 영향받는 행을 갱신하고 이전 검색/선택/스크롤/원래 행·열로 복귀. 연결 원본 ID가 없는 경우 신규 원본으로 바꾸지 않는다.
- 검증: 두 코스의 공유 납품처, 원본 수정 vs 연결 교체, 보조 기사, 삭제/접근 불가 원본, 미저장/저장 중 닫기, 상세를 오간 뒤 키보드 복귀.

## 5/8 — 실패·검색·입력 피드백
수정 후보: Users/AuditLog/공통 목록 로더, useFeedback/Toasts, 원본 폼, PortalSearch/필터 사용처.

- 최초 로딩/기존 자료 갱신/0건/필터 0건/권한 불가/네트워크 실패를 분리한다. 갱신 실패가 기존 자료를 없애는 경로부터 수정한다.
- 새로고침하라는 문구만 남기지 않고 해당 요청 재시도, 이전 정상 화면으로 돌아가기, 실패한 필드 수정을 제공한다.
- 필수값·형식 오류는 필드 가까이에, 전체 실패는 폼 상태에 표시한다. 오류 토스트가 실제 입력 위치를 대신하지 않는다.
- 가벼운 목록 검색과 비용이 드는 서버/문서 검색의 실행 시점은 구분하되 범위/필터/결과 수/초기화 표시를 일관되게 한다.
- 검증: 첫 조회 실패/갱신 실패/검색 결과 0건을 각각 재현, 키보드 첫 오류 이동, 재시도 후 입력/필터 유지. 실제 직원 권한을 늘려 UI를 통과시키지 않는다.

## 6/8 — 도구별 처리 흐름
공통 표시 기준은 재사용하되 계산/파서/양식은 건드리지 않는다. 한 번에 모든 도구를 수정하지 않고 아래 순서로 작은 변경 묶음을 만든다.

1. Excel 비교·PDF: 파일/조건 보존 이후 입력 전 설정 과다를 줄이고 실행/결과 위치 정리. PDF 변환·병합·기사 서류 전송은 현재 작업을 구분.
2. 이배송·전표·이미지·배차 파서: 행 추가/수정/DB 저장/파일 생성의 차이, 위험 작업과 일반 작업 버튼 분리.
3. 평택·김해·거리: 이미 끝난 단계와 실패 항목, 재시도/검토 필요/실제 저장 구분. 실제 제공자 없이 성공을 꾸미지 않음.
4. 온도·원탑·쿠팡·업무/일일정리·Talkcloud: 템플릿/원문/분석/수정/결과/외부 연결 상태와 기존 보존 경로에 같은 표시 계약 적용.

완료 기준: 각 도구에서 입력→확인→실행→결과 위치가 명확하고, 부분 실패가 전체 성공처럼 보이지 않아야 한다. 실제 외부 호출이 없는 검사는 ‘대역’으로 남긴다. 파일/업무를 자동 전송하는 새로운 기능은 추가하지 않는다.

## 7/8 — 화면 정리·접근성
- 목록 최초 진입에 빈 신규 폼을 무조건 펼치지 않는 방향. 사용자가 선택/신규를 누르면 기존 우측 패널을 열고 폭/접힘을 기억한다.
- 좁은 폼의 라디오/주소/연락처/날짜 label과 버튼 간격을 정리한다. 필드를 삭제하거나 업무 컬럼을 요약해서 없애지 않는다.
- 본문 제목/설명 반복, 시스템 연결 설정의 과도한 노출, 삭제/전체 초기화와 주요 저장의 비중을 정리한다. 기존 사용자에게 필요한 설정은 찾을 수 있게 유지한다.
- 일상 작업에는 명료한 한국어 조작명. 내부 DB/RPC 등의 설명은 오류 진단/관리 범위에 한정한다. 브라우저 언어에 따른 네이티브 버튼 차이는 별도로 확인한다.
- Notion 잔존 메뉴·일시중지 안내를 사용자 폐기 결정과 일치시킨다. 재연결 기능을 만들지 않는다.
- 1366×768/1440×900 PC, 라이트/다크 안정 상태, 확대, 긴 이름·빈 값·많은 행, Tab/Enter/Escape/F2·포커스 복귀·모션 감소를 필요한 화면에서 확인한다. 색만으로 상태를 구분하지 않는다.
- 테마나 유리 재질 전체 교체는 범위 밖. 실제 대비/초점 결함만 수정하고 취향 차이를 결함으로 집계하지 않는다.

## 8/8 — 누락 마감
- 점검 보고서의 35개 화면을 `적용 완료 / 기존 동작 적합 / 명시적 제외 / 미확인`으로 갱신한다. 제외 사유 없는 빈칸을 남기지 않는다.
- 대표 동선: 로그인→대시보드→코스→납품처→기사→원위치, 목록 검색→상세 수정→저장 실패/재시도→복귀, 파일 도구 준비→다른 화면→재개→결과, 업무/보고 현재값과 이력 확인.
- 각 화면에서 모든 외부 API를 반복 호출하지 않는다. 실제 로그인·실제 자료·외부 제공자·Windows 실기를 합성 화면 확인과 구분한다. 실제 업무 값은 시험 목적으로 임의 변경하지 않는다.
- 통과 기준은 불필요한 강제 인증 수, 전역 차단 여부, 입력/선택/스크롤 유지, 저장 결과의 정확성, 원본/연결 구분, 키보드 복귀다. API 실제 소요시간과 UI가 조작을 막는 시간을 따로 측정한다. 근거 없는 전체 속도 개선율은 보고하지 않는다.
- 실제 환경 확인이 남으면 ‘격리 UI 검증 완료 / 운영 확인 미완료’로 남긴다. 전체 기능 완료라는 표현으로 미적용 화면을 감추지 않는다.
