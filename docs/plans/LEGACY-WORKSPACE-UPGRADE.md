# 기존 웹 구조 개선 — 7단계 실행안

기준: 2026-11-13, SAJOANSAN main fb75f7f. 새 ERP 이관 대신 기존 웹·Supabase를 유지한다.
사용자 지시: 구상안을 별도 저장하고 단계별 실행. 각 완료 보고에 총 7단계 중 진척도 명시. 브라우저는 내부 브라우저 사용.

## 지켜야 할 구분
원본·관계·연결별 조건·분류 속성·과거 스냅샷·화면 작업 문맥을 구분한다. 관계에서 속성/권한을 자동 복사하지 않는다. OP와 일반 직원의 기존 접근 계약 유지. Notion은 사용자 폐기. 기존 저장 버튼/Enter 방식, 시간·OTD 의미와 원본 ID를 유지한다.

| 단계 | 원래 항목 | 구현 범위 | 완료 기준 | 상태 |

후속 단계의 구체 파일은 직전 완료 결과와 실제 코드에 맞춰 좁게 확정한다. 범용 엔진/새 UI 프레임워크/새 권한 체계는 만들지 않는다. 한 단계 구현·검증·배포 상태를 구분해 보고하고 다음 단계로 진행한다. 모든 도구 완료나 운영 검증을 합성 검사로 대신 주장하지 않는다.

## 첫 단계 실행 범위
- 재사용: catalog-scope, routes, delivery-points, dashboard-edit, EditorStatus, ChangeReview, 기존 route_stops RPC.
- 원본 ID+updated_at로 부분 수정. 같은 결과의 재조회는 재시도 수렴 확인이며 영속 영수증이 아니다.
- 실패/충돌 시 초안 보존. 최신값 조회 자체는 저장/권한 확대를 하지 않는다.
- 코스 폼은 전체 필드 덮어쓰기 대신 실제 변경 필드만 전송.
- 제품 DB 스키마·권한·이력 체계 신설 없음. 기존 RLS/이력을 사용.
- 별도 테스트 파일을 저장소에 만들지 않고 임시 합성 검증/기존 빌드를 사용한다.
