# 김해 배차 회신·사진 입력 수정 (2026-11-17)

## 범위와 재현

- 시작 소스: `2991c30089868904457e7ab3c49ca21c83400eca`, SAJOANSAN.
- 요청: 광주 2대·전주 1대·하양 2대 입력 후 하양 추가 차량을 요구하는 문제, PC 사진 붙여넣기 시 파일창이 열리는 문제.
- 사용자 추가 결정: 고정차 기능 제거. 회신의 `평택→김해` 표기는 사용자가 `김해→하양` 오타라고 확인했으며, 일반 회신의 해당 노선을 자동 치환하지 않는다.
- 고정차가 요청 칸을 먼저 차지하면 다른 번호의 회신 차량은 별도 미연결 행으로 추가됐다. 별도로 `냉동3`과 `냉동&냉장` 요청을 문자열 일치로 판정하여 연결을 놓쳤다. 격리 재현에서는 요청 2칸과 미연결 차량 2행이 남았다.
- 원문 보정은 앞의 `ㅡ`·`-`, `20_00`, 온도 없이 적힌 `16p` 블록을 놓쳤다. 사진 영역은 버튼 전체가 파일 input을 클릭하는 구조였다.

## 변경

- `GimhaeDispatch.tsx`: 고정기사 설정·오늘 포함 UI, 기본값 조회·저장 호출, 날짜 변경·새 작업 자동 반영과 복사 대기 조건 제거. 기존 DB 기록은 삭제하지 않았다.
- `domain/gimhae.ts`: 요청 칸 생성에서 고정차 자동 삽입 제거. 단일 온도 상차는 혼적 요청과 호환되도록 하되 정확한 단일 온도 요청을 우선한다. 서로 호환되지 않는 온도와 미확인 목적지는 확인 대상으로 유지한다.
- 차량번호·기사·전화가 명확한 블록은 원문 구분선, 시간, 물량을 보존한다. 차량 뒤의 공통 요청/안내/예상출고량은 개별 차량 조건에 섞지 않는다. P 수량을 실제 톤수로 채우지 않는다.
- 사진 영역 클릭은 포커스만 부여하고 기존 paste/drop 처리를 재사용한다. 파일창은 별도 버튼으로 연다. 공통 곡률과 키보드 포커스 유지.
- 기존 분석 제공자·모델·프롬프트, 로그인·권한, DB 스키마는 변경하지 않았다.

## 확인

- `node app/node_modules/typescript/bin/tsc -b app`: 통과.
- app 디렉터리에서 `node node_modules/vite/bin/vite.js build`: 통과. 기존 PGlite eval/externalize 및 큰 번들 경고는 남아 있다.
- 기존 환경의 임시 Node 검증: 회신 순서·접두 구분선·공통 안내문 유무 12개 조합, 재적용 ID/건수 유지, 직렬화·복원, 미확인 목적지, 잘못된 온도 연결 확인.
- 광주 2 + 전주 1 + 하양 2 = 5대. 과거 고정기사 기본값이 들어 있는 입력에서도 신규 요청에 자동 삽입되지 않고, 회신 재적용 후 하양 2대 유지.
- Ego Lite 격리 화면: 사진 영역 클릭의 파일 input 호출 0회, 명시적 파일 선택 1회. 합성 paste 이벤트→사진 분석→하양 회신 반영→2·3번 도크·20:00·물량 유지, 재분석 버튼은 API 재호출 없이 이미 반영된 회신으로 처리.
- 위 브라우저 분석은 모의 API 응답이며 실제 모델 호출 성공과 구분한다. 라이트 결과 화면·다크 입력 화면 확인. Impeccable detect 결과 `[]`.
