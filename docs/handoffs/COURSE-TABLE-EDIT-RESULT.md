# 기존 웹 코스표 직접 편집

기준: 2026-11-12. 대상은 SAJOANSAN 대시보드 코스표다. 별도 ERP 운영이나 DB 이관을 재개하지 않는다.

## 원인과 변경

- 시작 운영/main: `39696aaadab9f71dae5198e6d9b51dcbdd3dfbf4`.
- 작업 브랜치: `codex/course-table-edit`.
- 기존 표의 셀에는 저장 동작이 없었고, 행 클릭은 납품처 상세를 열었다. 코스·기사·차량·운수사는 별도 관리 화면으로 이동해야 했다. 코스/납품처의 기존 초안도 실행 중 메모리 보관이었다.
- 코스표 셀에서 편집하는 작은 창을 연결했다. Enter·저장·다른 셀 선택·편집창 밖으로 이동할 때 저장하며, Esc/취소는 해당 입력을 버린다. 입력 중 매 글자마다 서버에 쓰지 않는다.
- 저장 중/저장됨/실패를 구분한다. 서버 성공 후 코스표와 연결 기사 보건증 현재값을 다시 조회한다. 실패하거나 충돌하면 입력을 유지한다. 최신값 확인은 자동 덮어쓰기가 아니며 사용자가 재검토를 명시적으로 선택한 후 다시 저장해야 한다.
- 미저장 셀의 입력과 읽은 수정시각·정차지 스냅샷을 로그인 사용자별 sessionStorage에 보관한다. 같은 탭의 새로고침 후 ‘미저장 셀 복원’으로 복원한다. 다른 셀을 눌러 기존 초안을 조용히 지우지 않는다. 탭 종료/다른 PC 동기화 기능은 아니다. 저장소 사용이 차단되면 알린다.
- 저장 시 기존 필터·정렬·열 구성과 표 DOM을 유지한다. 편집을 닫으면 셀로 키보드 포커스를 복귀시킨다. 기존 행 상세와 5개 관리 페이지도 유지한다.

## 수정 대상과 소유 관계

| 셀 | 저장 대상 |
|---|---|
| 코스명·호차 | 해당 코스 기본정보 |
| 운수사·주기사·차량번호 | ‘이 코스의 연결’에서 안정 ID로 연결 변경 / 공통정보에서 연결 원본의 이름·번호 수정 |
| 기사 연락처·차량 톤수 | 연결된 주기사/주차량의 공통 원본 |
| 납품처 | 해당 정차지의 연결 교체 / 공통 납품처 이름 수정 |
| 납품처 코드·지역·주소·연락처·열쇠·비밀번호·진입조건 | 공통 납품처 |
| 순서·입차·하차 시작/종료 | 해당 코스 정차지 |
| 납품방식·진입방식·납품장소·마감·비고 | 코스별 값과 공통 납품처를 구분하여 선택 |

정차지 교체·순서 저장은 기존 `legacy_save_route_stops`를 사용한다. 연결 ID와 다른 코스·원본은 보존한다. inherit/set/clear, 명시적 빈 문자열, NULL, 0, false를 구분한다. 시간은 현재 웹의 00:00~23:59 규칙을 재사용한다. 별도 관리 화면의 모든 필드·등록/삭제를 표에 복제한 작업은 아니다. 보건증 셀의 기존 복사 동작은 유지한다.

## 권한·DB·영향 범위

- 실제 로그인 사용자의 Supabase 클라이언트·원본별 수정 권한·RLS를 그대로 사용한다. 직원의 센터 선택을 원본 권한으로 대입하지 않고 편집 시작 시 실제 원본의 속성과 권한을 확인한다.
- 공통 원본은 변경 필드만 `id + updated_at + deleted_at IS NULL` 조건으로 저장한다. 0행 결과를 성공으로 보지 않는다. 응답 유실 재시도는 현재 필드가 이미 같은 경우만 쓰지 않고 인정한다. 최신 수정시각을 자동 대입해 충돌을 우회하지 않는다.
- 운영의 다섯 원장에 `trg_set_updated_at`·변경 이력·삭제 참조 보호가 존재함을 읽기 확인했다. 정차지 순서가 1부터 연속되지 않는 운영 코스는 0개였다.
- SQL/migration/DB 정책/서버/API 권한·ERP 설정은 변경하지 않는다. 업무값을 시험으로 수정하지 않는다.
- 변경 코드: `Dashboard.tsx`, `DashboardCellEditor.tsx`, `dashboard-edit.ts`, `dashboard.ts`, `dashboard-edit.css`. 기존 관련 검사 2개에 사례를 보완했다. 새 패키지·저장 엔진·별도 테스트 체계는 없다.

## 검증

- `node app/node_modules/typescript/bin/tsc -b app`: 통과.
- app에서 `node node_modules/vite/bin/vite.js build`: 통과. 기존 PGlite의 node:module/eval 및 큰 번들 경고는 남아 있다.
- `PGLITE_MODULE=<기존 설치 경로> LEGACY_CATALOG_ONLY=1 node tests/portal-permissions.test.mjs`: 통과. 실제 로컬 PostgreSQL(PGlite)에서 새 셀 저장 함수의 공유 수정, 재조회, 응답 유실 후 무중복 재시도, 오래된 수정시각 충돌, 기존 정차지 RPC, 납품처 교체의 관계 ID 유지와 다른 코스 보존, viewer 거절을 확인했다. 테스트용 Supabase query facade로 SQL을 실행했으며 운영 PostgREST 쓰기 검증은 아니다.
- `node tests/unassigned-delivery-points.test.mjs`: 통과. 원본/연결 소유, 조건 상속·비움·빈 값, 0시, 유효하지 않은 시간/순서, 안정 ID 순서 변경.
- `node tests/dashboard-health-display.test.mjs`: 통과.
- Impeccable detect: 변경 UI 대상 결과 `[]`. 기존 라이트·다크 표면과 폰트 사용.
- Ego Lite 격리 화면: 셀 이동 자동 저장, Enter 저장, 저장 후 새로고침, 공통 주소 반영, 실패 후 입력 유지, 실패 입력의 새로고침 복원·재시도, 최신값 비교 후 명시적 재검토, 납품처 교체, 연결별 clear와 공통값 보존, 키보드 포커스 복귀를 확인했다. 기존 브라우저 fixture를 재사용한 모의 API 검사이며 실제 운영 저장으로 보고하지 않는다.

## 배포·운영 확인

구현 검사 완료. 운영 배포와 실제 계정 화면 확인 결과는 배포 후 이 항목에 기록한다.

운영에서는 기존 계정으로 코스표의 필요한 업무값 한 건을 수정하고 ‘저장됨’을 확인한 뒤 새로고침하여 확인할 수 있다. 운영 시험 데이터는 만들지 않는다.

## 복구와 제한

프런트 문제 시 직전 Vercel production 배포로 되돌린다. 이미 정상 저장된 공통 원본·정차지·변경 이력은 유지하며 DB를 과거 사본으로 덮어쓰지 않는다. 기존 관리 페이지는 계속 사용할 수 있다. 다른 탭/PC의 실시간 푸시 갱신이나 전체 원장 관리 화면 재구축은 이번 변경에 포함하지 않는다.
