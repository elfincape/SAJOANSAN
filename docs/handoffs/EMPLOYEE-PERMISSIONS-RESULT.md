## 확인한 원인과 수정

1. 역할·센터 설정의 PortalPermissionPreview가 모든 업무를 센터별 반복 열로 출력했다. 업무/허용 동작/자료 범위의 접힌 미리보기로 교체했다. 실제 편집은 선택한 직원의 업무 권한 화면으로 연결한다.
2. 기존 직원별 편집기에도 단일 적용 확인 센터가 있었고, 지정 사용자 전용·관리자 전용이라는 제한 사유가 접근 결과와 섞여 있었다. 센터 선택을 제거하고 업무별 허용 동작, 조회 범위, 수정 범위, 접근 불가 사유를 구분했다. 공통 원장 전체 범위에는 미분류 포함을 표시한다.
3. 빈 센터 값의 프런트 미리보기가 조건 없는 조회로 처리됐다. 운영 SQL은 빈 값을 미분류 자료로 판정한다. React와 구형 JS의 effectivePermission 모두 undefined/null과 빈 문자열을 구분하도록 수정했다.
4. 직원·권한 전체 JSON을 React key로 사용해 새로고침 시 편집기가 재생성되고 초안이 사라졌다. 직원 ID를 key로 사용하고 직원별 초안과 최초 버전을 보관한다. 다른 직원 선택 후 복귀 시 초안을 유지하고, 최신 권한/직원 정보가 바뀌면 입력을 보존한 채 오래된 저장을 막는다.
5. 현재/변경 후 적용 결과, 변경한 업무 필터, 업무 검색, 변경 취소를 제공한다. 역할 설정 링크가 선택 직원을 유지하며 URL 직원 선택을 이전 화면 캐시보다 우선한다.
6. 라이트·다크에서 중복으로 보이던 접근성 라벨과 세로로 쌓이던 필터를 정리했다. 기존 공통 스타일과 Radix 탭을 사용하며 새 패키지는 없다.

## 권한·저장 계약

- 기존 operations_update_member_permissions RPC 및 member_overrides를 재사용한다. 관리자 확인, 직원 정보·규칙 버전 비교, 요청 ID 중복 방지, 트랜잭션, 변경 이력을 유지한다.
- 일반 직원의 조회 전용 역할, 명시적 거부, 담당 범위, 비활성 제한 및 관리자/지정 사용자 전용 경계를 유지한다. 이메일로 OP 권한을 부여하지 않는다.
- 화면 수정은 실제 계정에 새 권한을 일괄 부여하지 않는다. 기본 권한과 직원별 지정값을 분리하고 기존 설정을 유지한다.
- DB 함수·RLS·기존 직원 권한 데이터는 변경하지 않았다. 운영 함수 정의를 확인했으며 기존 저장 경로를 그대로 사용한다.
- 삭제 표시는 공통 원장 soft-delete 등 기존 관리 동작의 edit 판정을 뜻한다. 별도의 삭제 권한이나 hard-delete 경로를 추가하지 않았다. 업무별 담당자·상태·소유자 제한은 기존대로 추가 적용된다.
