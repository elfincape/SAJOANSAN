# 화면 이동 인증 반복 — 8단계 후속 수정

2026-11-13, SAJOANSAN, `/workspace/legacy-workspace-upgrade`, 시작 `f7128475bef4755b7d54fb0f8ab99fdb43684d21`, 브랜치 `codex/auth-navigation-followup`.

사용자가 운영 화면에서 여전히 로그인·권한 확인이 반복된다고 보고했다. 앞선 13개 내부 이동 검증만으로 반복 인증 문제를 마감한 것은 불충분했다. 기존 보고서는 보존하고 이번 누락과 보완을 별도로 기록한다.

## 재현된 원인

1. PDF 등 네이티브 문서 이동은 React 모듈 메모리도 초기화한다. 기존 30초 캐시는 문서 밖으로 유지되지 않아, 도구를 열고 허브로 돌아오는 것만으로 `getUser`·프로필·권한 RPC를 다시 조회했다.
2. Supabase의 `SIGNED_IN`은 실제 새 로그인뿐 아니라 같은 세션 확인/탭 재포커스 때도 발생한다. 기존 코드가 모두 캐시를 무효화했다. 설치된 `@supabase/auth-js/src/GoTrueClient.ts`의 이벤트 계약과 일치한다.
3. AdminPage는 빠르게 복원될 때도 첫 렌더부터 인증 문구를 표시했다.

앞선 대역은 `onAuthStateChange` 콜백을 호출하지 않았고, 내부 연속 이동만 측정했다. 이번에는 네이티브 문서 왕복과 반복 SIGNED_IN을 추가했다. 실제 사용자의 로그인 세션이나 비밀번호를 사용하지 않았다.

## 변경 범위

- `app/src/lib/auth.ts`: 서버에서 확인한 화면용 인증 컨텍스트를 같은 탭의 `sessionStorage`에 보관한다. 먼저 현재 Supabase 세션을 읽고 사용자 ID와 접근 토큰의 SHA256 지문이 모두 일치하는 경우에만 재사용한다. 토큰 자체는 추가 저장하지 않는다.
- 기존 **30초** 상한과 최초 검증시각을 유지한다. 문서 이동/복원으로 유효시간을 늘리지 않는다. 잘못된 데이터·미래 시각·다른 계정/토큰·비활성 프로필은 복원하지 않는다. 저장소/crypto 미지원이면 기존 서버 확인으로 돌아간다.
- 동일 계정·동일 토큰의 SIGNED_IN 재알림만 재사용한다. 로그아웃·사용자 정보 변경·토큰 갱신·다른 계정/토큰·명시적 refresh는 무효화한다.
- `app/src/components/AdminPage.tsx`: 빠른 세션 복원에서 인증 문구가 깜박이지 않도록 250ms 이후에도 대기 중일 때만 표시한다. 데이터 화면은 실제 컨텍스트 준비 전에는 렌더링하지 않는다.
- 클라이언트 캐시는 화면 상태의 재사용이며 서버 권한의 증명이 아니다. DB/RLS·Edge/서버 요청 검증·실제 권한/역할 정책은 변경하지 않았다. 권한을 무기한 저장하거나 익명 접근을 허용하지 않는다.

## 실제 확인

임시 `/tmp/auth-navigation-followup`에서 기존 Playwright·Chromium과 실제 Vite React 화면을 사용했다. Supabase 응답은 합성 대역이며 외부 HTTPS 요청은 차단했다. 영구 테스트 파일/패키지를 추가하지 않았다.

- 수정 전 코스→PDF→허브→Excel→코스: `getUser` 누적 **3회**, PDF/허브 진입에서 인증 문구 표시. 같은 세션 SIGNED_IN 후 재조회도 별도 실패 재현.
- 수정 후 같은 동선: 최초 **1회** 유지, 각 이동의 인증 문구 **미표시**. 이후 같은 계정 SIGNED_IN→기사 이동에서도 1회 유지.
- 저장된 검증시각을 31초 전으로 만든 뒤 문서를 새로 열면 서버 재조회 2회째 발생: 만료 우회 없음.
- VM 검사: 동시 조회 합치기, 같은 세션 이벤트, 문서 초기화 뒤 복원, 원래 TTL, 다른 토큰/계정, 강제 refresh, 손상/미래 시각 캐시, 비활성/로그아웃, 저장소 차단 통과.
- 기존 auth VM 검사 통과. 연결 상세의 부모 인증 재사용·변경 후 부모 표 갱신 브라우저 검사 통과.
- `node --test tests/portal-permissions.test.mjs`: 통과.

## 검증 한계와 기대 동작

첫 접속, 30초 유효시간 경과, 세션/계정 변경, 브라우저 저장소 차단 등에는 새 권한 확인이 필요하다. 이를 삭제한 수정이 아니다. 전문 도구의 문서 이동 자체는 유지하며 같은 탭에서 아직 유효한 검증 결과를 연결한다. 브라우저 재시작이나 모든 상황에서 인증 대기가 사라진다고 보장하지 않는다.

사용자의 실제 로그인 환경에서 발생한 횟수·서버 응답시간은 직접 측정하지 않았다. 위 수치는 실제 React 브라우저 동선에 합성 인증 응답을 연결한 재현 결과다. 운영 배포 커밋·READY·공개 주소 확인은 최종 응답에 별도로 남긴다.
