# 공통 상세창·하단 작업·스크롤 통일

2026-11-16. SAJOANSAN main `41d1e31` 이후 변경. 기존 대시보드 상세에서 다른 페이지의 상세까지 확장했다.

## 적용

- 기존 Radix Modal과 native PortalDialog/배차 dialog가 같은 DialogFrame을 사용한다. 본문만 스크롤하고 DialogActions는 스크롤 밖의 하단 영역에 표시된다. 버튼을 DOM으로 강제 이동하지 않고 React portal 및 HTML form 연결을 사용한다.
- 코스·정차지 등록/수정, 대시보드 행 상세, 확인창, 일일정리 상세·메시지 입력, 포털 업무 상세·등록·조사·설계·특이사항, 용차 운행 편집, 배차 하차 조건 및 김해 고정기사 편집의 작업 버튼을 연결했다.
- 코스 관리의 납품처 편집 진입도 기존 LinkedRecordDetail을 재사용한다. 별도 사각 iframe 모달을 제거하고 부모 인증 재사용·원본 저장 알림·초안 보호를 유지한다.
- 공통 사이드바 재질·24px 외곽·12px 버튼·18px 작업 그룹, 무테, 가는 투명 트랙 스크롤을 적용했다. 오른쪽 모달/포털 상세의 화면 끝에 붙는 0px 모서리를 제거했다.
- 기존 바깥 클릭/취소, 저장 중 잠금·권한·폼 검증을 유지한다. native 도구는 기존 cancel 처리에 바깥 클릭을 연결한다. 업무 계산/모델/DB/저장 함수는 교체하지 않는다.
- 제출 버튼을 footer로 분리한 코스·정차지와 native 편집 폼, 포털 작성 폼에는 원래 form 연결을 명시했다. StopForm의 취소는 초안 제거 후 기존 close도 실행한다.

## 확인

- TypeScript, Vite 빌드 통과. 기존 큰 번들/PGlite 경고 유지.
- 기존 charter-review, delivery-point-dashboard-content 검사 통과. Impeccable 공통 UI 검사 결과 `[]`.
- Ego Lite 기존 격리 API fixture에서 코스 관리 편집 열기, 실제 form 제출·저장·취소 및 라이트·다크를 확인했다. 본문 하단과 footer 상단의 좌표를 대조해 겹침 없음을 확인했다.
- 실제 PortalDialog 컴포넌트를 격리 화면에서 렌더해 긴 본문 스크롤·하단 form 제출 1회·바깥 클릭 닫힘을 확인했다. 이 검사는 운영 포털 업무 저장 검증이 아니다.
- 각 업무의 실제 데이터 저장은 시험하지 않았다. DB/권한 변경 없이 프런트만 배포한다. 운영 후 읽기 화면 확인은 후속 기록으로 구분한다.

## 복구

문제 시 직전 Vercel 프런트로 복구한다. 기존 업무 데이터·인증·권한·초안·ERP 보관본은 변경하거나 되돌리지 않는다. 다른 도구의 계산·일괄 작업 전체 회귀를 수행한 것으로 보고하지 않는다.
