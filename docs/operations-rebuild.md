## 최소 데이터 설계

- 일반·반복·개인·HQ 업무는 하나의 논리적 업무 원본을 사용한다. 유형별 추가 입력은 템플릿 설정과 해당 업무에 보관한다. 작업 단계별 DB를 만들지 않는다.
- 템플릿은 센터·유형·버전으로 구분한다. 승인된 버전만 신규 업무에 적용한다. 기존 입력과 완료 기록은 보존한다.
- 특이사항은 기존 사건 원본을 유지하고 관련 업무·마스터를 연결한다. HQ 지원은 원본의 요청 상태와 실제 조치 기록으로 구성하며 사건을 복제하지 않는다.
- 일일 기록은 업무 및 사건의 실제 처리 이벤트로 조회한다. 직원용 추가 일일보고 원본을 만들지 않는다.
- 업무조사 원본과 템플릿은 승인 전후 수명주기가 달라 구분한다. 조사·설계·구축·운영 검증 상태를 구분하며 조사 완료를 전체 완료로 표시하지 않는다.
- 기존 감사 이력을 조사해 처리 이력에 재사용할 수 있는지 결정한다. 파일 실행 상태와 재시도 키는 서버에 보관하고 직원 화면에서는 숨긴다.

## 권한 및 API 경계

센터 화면의 필터·URL·localStorage는 권한이 아니다. 업무별 센터 수정 권한은 실제 소속을 서버에서 검증한다. HQ는 모든 센터를 수정할 수 있으며 특이사항 해결/재개는 지시서의 공통 예외를 적용한다. 마스터 원본 및 확정된 과거 기록을 잘못 변경할 수 없도록 이력을 분리한다.

Notion 원본 읽기 권한과 센터 구성원 속성의 페이지 수정 권한을 조합하는 방식을 우선 검토한다. 현재 워크스페이스의 플랜과 상속된 권한을 실제 확인하기 전에는 적용 가능/완료로 표시하지 않는다. 페이지별 권한은 Business/Enterprise 기능이며 가장 넓은 권한이 우선한다. [공식 권한 문서](https://www.notion.com/help/sharing-and-permissions).

공식 Block API에서 button은 unsupported 유형이다. 연결 도구의 unknown 블록과 일치하지만 이것만으로 UI 생성이 불가능하다고 단정하지 않는다. 시험용 실제 페이지에서 기본 도구·브라우저 경로를 먼저 검증하며 TinyFish는 마지막 대안이다. [공식 Block 문서](https://developers.notion.com/reference/block).

OneDrive 개인 저장소 권한은 직원에게 부여하지 않는다. 인증된 서버에서 허용된 폴더와 파일만 접근한다. 시험 환경에서 운영 OneDrive 연결 토큰을 복사하지 않는다. 생성 파일과 외부 전달 완료는 별도로 기록하며 CJ 자동 전송은 구현하지 않는다.

## 시험 DB 업무 기반 구현 (2026-10-11)

격리된 시험 프로젝트에 기존 인증과 호환되는 user_profiles·centers를 준비하고, operations-core.sql을 실제 적용했다. 센터는 기존 코드 001·002만 등록했다. 실제 직원 배정이나 운영 계정을 복제하지 않았다.

업무 원본 operations_tasks 하나, 변경 이력 operations_task_events 하나, 수정 소속 operations_center_members로 구성한다. 일일·주간 기록은 이력의 한국시간 날짜를 조회하는 operations_daily_log 뷰이며 별도 보고서 입력 DB가 아니다. 생성자·담당자·완료자·시간을 서버가 기록한다. 업무 입력은 해당 원본의 JSON에 보관한다. 직원에게 이력/권한 테이블 입력을 요구하지 않는다.

업무 변경은 인증된 RPC만 허용한다. 직원은 배정된 센터만 수정하고 다른 센터 업무를 조회할 수 있다. 기존 admin 역할을 HQ 권한 후보로 사용하며 실제 운영 사용자와의 대응은 아직 확정하지 않았다. viewer 쓰기, 비활성 조회, 익명 접근, 직접 테이블 수정은 거부한다. 요청 번호로 재시도를 중복 생성 없이 처리하며 수정 버전이 다르면 덮어쓰지 않는다. 완료·해당 없음 원본은 후속 변경을 차단해 확정 입력을 보존한다. 해당 없음 사유는 요구하지 않는다.

tests/operations-core.integration.sql을 실제 PostgreSQL에서 실행하여 생성→진행→완료, 동일 요청 재시도, 요청 번호 재사용 거부, 오래된 버전 수정 거부, 완료 보존, 해당 없음, 자동 일일 이력, 월대공제 조회 및 센터/HQ/viewer/비활성/익명 권한을 통과했다. 모든 시험 계정·업무는 같은 트랜잭션에서 롤백했다. scripts/operations-staging.mjs는 시험 ref 외에는 실행을 거부한다. operations-api.js는 기존 로그인 클라이언트를 재사용하는 저장·기간 조회·정산방식 조회 어댑터다.

tests/operations-http.integration.mjs로 시험 프로젝트에만 임시 계정을 생성하여 실제 비밀번호 로그인→업무 생성→같은 요청 재시도→다른 센터 수정 HTTP 403→완료자 기록→자동 일일 기록 조회→익명 접근 거부를 통과했다. 임시 업무·이력·소속·프로필·Auth 계정은 finally 정리 단계에서 모두 제거했다. 서버용 키는 실행 중 메모리에서만 사용하고 파일·로그에 출력하지 않는다.

이 단계에서 업무 기반과 실제 DB·로그인 HTTP 검증을 완료했다. 후속 인계·특이사항·승인 양식 구현은 아래에 기록한다. 운영 main/DB/Notion은 변경하지 않았다.

## 인계·특이사항·HQ 공동 조치

operations-workflow.sql을 시험 DB에 적용했다. 인계는 같은 업무의 담당자만 변경하며 입력·진행 상태·배송 기한·CJ 공유 기한을 유지한다. 이전/다음 담당자와 선택 메모는 기존 이력에 남는다. 기존 기한을 변경할 때만 사유를 요구한다. 완료된 업무의 인계나 기한 변경은 막는다.

특이사항은 operations_incidents 원본 하나를 유지하고 업무를 연결한다. HQ 요청과 실제 조치, 해결, 재개를 같은 원본의 이력으로 관리한다. HQ 조치는 여러 사람이 각각 기록할 수 있고 지원 완료가 사건을 해결하지 않는다. 메모 없는 단순 조회는 실제 조치로 기록하지 않는다. 해결·재개는 센터와 역할에 관계없이 활성 사용자에게 허용하는 명시된 예외다.

실제 SQL 및 비밀번호 로그인 HTTP에서 인계·권한·공동 조치·타 센터 해결/재개·원본 유지·이력 보존·자동 일일 기록을 통과했다. 모든 시험 자료를 롤백 또는 삭제했다. 업무 조회 어댑터는 과거 미완료를 기간 밖이라고 누락하지 않고, 여러 페이지를 조회하여 1,000행 제한에 따른 누락을 피한다.

## 승인 양식 및 반복 인스턴스

operations-templates.sql을 시험 DB에 적용했다. HQ가 초안을 생성·승인·사용 중지하며 버전별 승인자와 시간을 보존한다. 새 버전을 만들어도 기존 업무의 양식 스냅샷·단계·입력은 유지된다. 완료 시 해당 승인 양식에 정의한 실제 필수 항목과 단계 처리를 검사한다. 해당 없음에 사유를 강제하지 않는다.

일간·선택 요일·매월 지정일·1회 반복 날짜와 동일 양식 계열/날짜/담당자 인스턴스 중복 방지를 구현했다. 월에 없는 지정일은 생성하지 않으며 말일 대체 규칙을 임의로 추가하지 않았다. 현재는 인증된 생성 API 기반이며 예약 실행 연결은 아직 하지 않았다. 테스트 양식만 트랜잭션 안에서 승인했다. 조사하지 않은 실제 센터 절차나 운영 양식은 확정하지 않았다.

## 서버 Notion 연결 검증

전용 연결 ‘이안 운영 STAGING’(3f5b98bf-5f20-81f9-b23f-00272999cc29)을 생성했다. 실제 API 인증 및 시험 루트와 두 시험 데이터 소스 읽기는 성공했다. 그러나 운영 관리허브 원본 3f4b98bf-5f20-81c2-992e-fecda52668d7도 HTTP 200으로 읽혀 콘텐츠 범위가 시험 환경에 한정되지 않았다. configure-operations-notion.mjs의 검증이 이 상태를 거부하여 Supabase 서버 시크릿 등록 전에 중단했다. 사용자에게 시험 루트 및 하위 페이지만 남기는 콘텐츠 권한 수정을 요청했다. 운영 페이지 수정은 수행하지 않았다.

후속 권한 수정 후 실제 API 재검증에서 시험 루트와 두 원본 읽기 성공, 운영 마스터 홈과 코스 원본 접근 거부(403/404)를 확인했다. 검증을 통과한 전용 연결 설정을 시험 Supabase 서버에 등록했다.

operations-notion.sql을 시험 DB에 적용했다. 노션 사용자 ID와 실제 활성 웹 사용자 매핑은 직원에게 노출되지 않는 서버 전용 테이블이다. 노션 입력은 operations_save_task를 재사용하여 센터 권한·수정 버전·중복 요청·완료 조건·완료자 기록을 동일하게 검사한다. SQL 시험에서 실제 수정자 기록, 재시도 중복 방지, 타 센터 수정 거부, 미연결/비활성 사용자 거부, 일반 클라이언트의 수정자 사칭 거부와 매핑 조회 거부를 통과했고 모두 롤백했다.

업무 속성 변환과 기존 3방향 병합 재사용 모듈을 검증했다. 노션에 노출하지 않은 내부 단계·마스터 문맥은 보존한다. 실제 직원 매핑은 아직 등록하지 않았다. 서버의 실제 동기화 실행기·예약 실행·버튼 연결은 후속 구현 대상이다. 이 기반 검증을 양방향 자동 동기화 완료로 표시하지 않는다.

## 쿠팡 기존 엑셀 생성기 재사용

기존 sazocoupang.xlsx와 ExcelJS 생성 로직을 coupang-workbook.js로 공유했다. 브라우저 다운로드는 같은 생성기를 호출하며 서버에서도 의존성을 주입하여 사용할 수 있다. 서버 모드는 미입력·시간 범위·행 용량 초과를 거부한다. 브라우저는 기존 부분 작성과 오류 안내를 유지한다. 생성 중 입력 변경이 파일에 섞이지 않도록 입력을 캡처한다.

실제 ExcelJS로 기존 양식을 읽고 XLSX를 생성한 뒤 다시 열어 날짜·요일 시트명·시간별 기사/센터·스타일·원본 시간표·이미지 ZIP 관계를 확인했다. 잘못된 입력 거부 및 기존 부분 작성 테스트도 통과했다. 실제 OneDrive 저장·Notion 파일 연결·전달 완료 기록은 아직 구현되지 않았다. 파일 생성 성공을 전달 완료로 처리하지 않는다.
