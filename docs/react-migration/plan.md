# React + TypeScript 이전 사전 조사 및 승인안

기준 저장소: `/workspace/SAJOANSAN`  
작업 브랜치: `react-migration`  
기준 커밋: `f083c1e3a2036019707dbd8c9249fd12a9f26137`

현재 단계는 코드 조사와 설계뿐이다. main 및 기존 소스는 변경하지 않았으며 app 생성, 패키지 설치, 화면 이전, 운영 DB 호출, 배포를 시작하지 않았다. 아래 순서를 사용자가 확인한 이후 구현한다.

## 1. 조사 범위

직접 작성한 HTML/JS/CSS, 연결된 API·서버·Supabase Edge 함수·SQL, 배포 설정·워크플로·검사 코드를 읽었다. 파일별 읽기 기록은 이 문서 옆 *-read.json에 보관한다. 패키지 잠금 파일은 의존성 데이터로 분석했고, 외부 라이브러리·생성된 dist는 재작성 대상에서 제외한다. 엑셀·이미지 바이너리는 코드처럼 읽었다고 간주하지 않으며 경로·참조·해시를 조사한다.

현재 앱은 이미 Vite 8 기반 다중 HTML 빌드다. React 전환은 빌드 도구 도입보다 DOM 렌더링·상태·공유 셸 이전이 중심이다. 실제 앱 진입 HTML은 33개(관리 30, 대시보드·로그인·포털 각 1)이며 포털과 평택 배차는 한 URL에 여러 화면을 포함한다.

## 3. 승인 후 이전 순서

0. `app/` Vite react-ts 기반, 기존 경로 호환 진입점, 공통 인증/센터/권한·테마·CSS 구조, 환경변수 및 npm 의존성 구성. 기본 설정 커밋을 화면 커밋과 분리한다.
1. 로그인. 공통 진입과 세션 복구부터 검증한다.
2. 기울기 보정 → 배차정보 파서 → 파레트 전표 → 엑셀 비교. 서버 의존이 적은 단순 도구부터 렌더링/파일 동작 검증.
3. 설정 → 관리 허브 → 중지 상태 Notion 화면 → 변경 이력. 기능 카탈로그와 공통 셸 검증.
4. 차량 → 운수사 → 기사 → 납품처 → 코스 목록 → 코스 편집 → 사용자. 공용 문서 패널은 운수사/기사에서 재사용하고 사용자 권한 이동은 기존 포털 주소를 보존한다.
5. 코스표 내려받기 → CSV 가져오기 → 이배송.
6. 온도 템플릿 → 1탑2실 작업 → 쿠팡 입문확인 → PDF 도구. 사진·양식·AI·문서 저장/취소와 부분 실패 검증.
7. 하불 계산 → 카카오 운행 정리 → 착지별 거리 → 네이버 최단거리 → 평택 용차내역 → 김해 배차 요청.
8. 평택 가배차. 내부 구성은 납품정보/도로 → 직접입력 단계 → CJ 가배차 순서로 구현하되, 기존 모드와 전체 URL 동작을 보존한다. 내부 화면별 커밋으로 진행한다.
9. 대시보드 → 운영 업무.
10. 포털 공통 셸 이후 센터 목록 → 업무 상세/발행·담당/인계 → 특이사항 → 본사 → 알림 → 업무 기록 → 검색 → 조사/양식 → AI 초안·브리핑 → 회원 → 페이지 권한 → 휴지통 → 연결 → 보관본 → 개인메일. 기존 access 경로도 보존한다. 각 화면 완료 시 별도 커밋.
11. 전체 기능·경로·반응형·밝은/어두운 모드·다운로드·API 배포 호환 확인, Vercel 전환 안내. 기존 파일 삭제/ main 병합/운영 Root 변경은 수행하지 않는다.

각 화살표의 화면을 하나 끝낼 때마다 기존 화면과 비교하고 관련 검사를 수행한 후 커밋한다. 여러 화면을 한꺼번에 DOM 래퍼로 감싸 이전 완료로 처리하지 않는다.

## 4. 코드 구성과 보존 원칙

- `app/src/lib/supabase.ts`: 환경변수 기반 단일 클라이언트. persistSession/autoRefresh/detectSession 동작 유지.
- `app/src/lib/`: 인증, 도메인별 기존 쿼리/RPC/Edge·파일 I/O 어댑터. 프런트엔드와 분리된 서버의 비밀키는 VITE 변수로 옮기지 않는다.
- `app/src/domain/`: 파서·계산·시간·배차·엑셀의 순수 모델을 기존 계약대로 TypeScript화. 숫자/빈값/null·날짜·ID·JSON 의미를 임의로 통합하지 않는다.
- `app/src/components/`, `app/src/pages/`: state/props/reducer 기반 UI. 행 ID/편집 초안·서버 저장본·작업중·오류·취소를 구분한다.
- 직접 DOM 기반 UI는 React로 변환. 영상·canvas·PDF·기존 grid/drag 라이브러리 등 브라우저 연동은 ref/effect와 정리 함수를 사용한다. React StrictMode 재실행으로 서버 쓰기·리스너·폴링이 중복되면 안 된다.
- 기존 CSS를 복사해 순서·페이지 범위를 유지한다. body 직계 자식 선택자와 React root wrapper 충돌만 동등한 구조/선택자로 조정한다. 테마·폰트·여백·색·표·모달·모바일 구조를 바꾸지 않는다. 페이지 전용 CSS를 모든 화면에 일괄 로드하지 않는다.
- 브라우저 CDN Supabase/SheetJS/PapaParse/Sortable/JSZip 등을 실제 사용 버전에 맞는 npm import로 전환. 기존 ExcelJS/AG Grid/PDF/solver 등은 재사용. 새 상태관리·UI·라우터 라이브러리를 임의로 추가하지 않는다. 서버 Deno import는 별도 범위.
- `/admin/*.html`, `/portal/`, `center/id/view/user/message` 파라미터, localStorage 키·버전, 딥링크, iframe postMessage 검증, OAuth 복귀 경로를 보존한다.
- `.env.example`은 빈 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 항목을 제공한다. `.env`, `.env.*`는 제외하고 `.env.example`만 예외 처리한다. 기존 node_modules/dist 제외를 확인한다. 기존 config 파일은 삭제/수정하지 않고 새 앱에서 사용하지 않는다.
- 기존 DB/RLS/RPC·Supabase Edge·AI/JEV·OneDrive 연결·외부 worker/scheduler와 현재 중지 상태를 전면 전환 이유로 변경하지 않는다.

## 5. 사전에 드러난 확인 항목

1. 사용자 수정 승인: Vercel Root Directory는 저장소 루트로 유지한다. api와 server를 app으로 이동하거나 재번들하지 않는다. Install은 cd app && npm ci, Build는 cd app && npm run build, Output은 app/dist로 설정한다. 기존 Node 함수의 루트 npm 의존성 추적·설치, 실행 지역 icn1·30/90초 제한을 최종 배포 검증에 포함한다.
2. `/templates/one-top-two-room-template_PYT.xlsx` 참조에 대응하는 파일이 저장소에 없다. 평택 양식 화면 이전 전에 원본 위치 확인이 필요하다. 임의 양식으로 대체하지 않는다.
3. root/templates와 assets/templates의 같은 이름 1탑2실 파일은 내용이 다르다. 이름만 보고 통합하지 않는다. 쿠팡 안내 양식명과 실제 fetch 양식명도 구별한다.
4. `charter-fuel-estimator.html`은 현재 거리 계산 화면이다. 연결되지 않은 유류비 UI/검사를 잘못 가져와 화면을 바꾸지 않는다.
5. CSV 가져오기 설명과 실제 동작(XLSX 미지원·upsert가 아닌 일부 insert), 사진 압축 안내/실제 fallback 등 기존 불일치는 별도 기록한다. 이번 이전에서 임의로 고치지 않는다.
6. SQL은 누적 패치 이력이다. 파일 하나나 파일명 정렬만으로 현재 DB 타입·최종 함수를 추측하지 않는다. 기존 호출 계약·후속 패치·기존 검사를 대조한다.
7. 일부 Edge의 CORS는 운영 도메인에 한정된다. Preview 검증을 위해 서버 허용 도메인을 임의 확대하지 않는다. 모의 검증과 실제 연동 검증의 결과를 구분한다.

## 6. 검증 및 완료 기준

- app에서 `npm run build`와 TypeScript 검사 통과. 기존 빌드도 원본 코드와 함께 유지한다.
- 화면마다 기존 검사 중 관련 항목을 실행/적응하고, 기존 화면과 같은 입력·권한·센터·상태에서 결과와 보이는 구조를 비교한다. 검사 통과를 실제 외부 연동 성공으로 과장하지 않는다.
- 외부 쓰기·배포·동기화가 섞인 check 스크립트는 이름만 보고 실행하지 않는다. 읽기 전용/모의 검증을 먼저 수행한다.
- 인증·권한·센터 격리, 수정 취소·중복 저장 방지·버전 충돌·부분 실패·초안 복구, 파일/사진/PDF/엑셀 셀·서식·사진·다운로드 검증.
- 배차는 원본 물량=배정+미배정, 실제 상차한도와 CJ 참고량 구분, 90%는 분할 검토 경계이며 실을 수 있는 본인 물량을 빼는 기준이 아님, 이력/당일 대조자료 구별·시간/방향별 주행·수동 조정·저장복원을 보존.
- 최종 Vercel 안내: Root Directory=저장소 루트 유지, install=`cd app && npm ci`, build=`cd app && npm run build`, Output=`app/dist`, Vite 환경변수·기존 링크 rewrite·API 함수 번들/지역/제한 확인. 모든 화면 동등성 확인 전 운영 설정을 바꾸지 않는다.

승인 요청: 위 목록·순서를 확인하면 app 기반 작업부터 시작한다. 현재 이전 완료 화면은 0개이며 빌드/실제 기능 동등성 검증은 아직 수행하지 않았다.
