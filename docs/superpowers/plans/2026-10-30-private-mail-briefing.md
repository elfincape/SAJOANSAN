# 개인 메일 일일정리 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 소유자 전용 웹 화면부터 메일 수집·분석·당일 OneNote 갱신까지 구현하고, 운영 연결 전 로컬 모의 통합검증을 완료한다.

**Architecture:** 기존 메일 테이블·Node POP 수집기·onedrive-auth를 재사용한다. 수집 큐, 분석, OneNote 쓰기는 별도 잠금과 체크포인트를 갖고, 서버 디스패처가 후속 청크를 이어간다. 실제 서비스 대신 모의 공급자와 로컬 PostgreSQL로 검증한다.

**Tech Stack:** 기존 JavaScript ES modules, node:test/assert, Microsoft OneNote HTML.

**Spec:** docs/superpowers/specs/2026-10-30-private-mail-briefing-design.md

## Global Constraints

- 대상은 할 일 목록 → 일일정리의 기존 섹션이며 새 섹션을 만들지 않는다.
- 제목은 한국 날짜 기준 YYMMDD 일일정리, 하루 한 페이지, 3시간 주기다.
- 수동 내용을 덮어쓰지 않으며 새 외부 호출·권한·예약을 이 단계에서 활성화하지 않는다.
- 기존 검사 파일을 재사용하고 별도 테스트 프레임워크·새 테스트 파일을 추가하지 않는다.

## 후속 실제 연동의 선행 조건

소유자 세션의 실제 수신·읽음 상태 보존 확인, 본문 분석 전송 범위 확인, 웹의 OneNote 접근 검증과 필요한 Microsoft 권한 동의, 예약 실행용 기존 서버 인증의 사용 가능 여부가 필요하다. 이 조건을 충족하기 전 실제 메일 분석·OneNote 쓰기·자동 수집을 실행하지 않는다.

## 운영 적용 보류와 남은 실검증

사용자의 재개 승인 후 Notes 연결용 최소 SQL만 정상 적용했다. 마이그레이션은 `20261030123236 / private_mail_notes_oauth`이며, 두 열과 전용 완료 함수의 존재, 기존 파일 함수의 `purpose='files'` 분리 및 기존 실행 권한 유지를 읽기 조회로 확인했다. 자동분석·필터·예약 SQL은 여전히 미적용이며 자동화를 활성화하지 않았다. Microsoft Notes.ReadWrite 연결, 서버 인증 설정 일치, 스케줄러 등록, 실제 50MB 호스팅 메모리·시간 제한은 검증 전이다. 사용자 실행 중인 수집 작업은 변경하지 않았다.

운영 `main`의 추가 변경 `2bf0d09`(기존 디자인 문서·CSS)을 보존해 병합했다. 병합 후 관련 검사 21개 파일, 앱 빌드, 소유자 전용·일일정리 모의 브라우저 검사를 다시 통과했다. 이번 배포의 우선 검증 대상은 사용자가 직접 동의할 수 있는 Notes 연결 화면이다. 실제 분석·OneNote 기록·예약 수집이 검증된 것으로 간주하지 않는다.

사진 원본은 보존한다. JPEG/PNG는 OneNote에 삽입하고 WebP는 분석 후 삽입 확인 필요 상태로 남긴다. 크기·개수 한도를 넘는 사진은 조용히 생략하지 않고 확인 상태로 둔다. 사진 PATCH 응답이 유실되어 실제 반영 여부를 판단하지 못하면 중복 삽입 대신 확인 상태로 중단한다. 이 예외의 무인 복구는 아직 보장하지 않는다.
