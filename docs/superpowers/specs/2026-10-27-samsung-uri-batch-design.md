# 삼성 사진 기간 전체 수집 — URI 전달

사용자 요구는 번호/기간을 지정하면 전체 수신 사진을 OneDrive에 전송하고 확인된 폰 임시 사본을 지우는 배치다. 한 장 저장 버튼 실행으로 완료라고 하지 않는다. 사용자는 해당 대화 사진 모두 상대방에게 받은 것임을 확인했다.

단말 메타데이터는 Download/, owner=com.samsung.android.messaging, media_type=1, JPEG, generation_added 정상이다. 실제 실패는 단계4 신규 파일 확인이며, 현재 수집 전후 MediaStore 차이 방식은 기존 저장본/사진 열기 중 생성 파일을 놓칠 수 있다. 이미 받은 사진에도 안정적인 입력을 얻으려면 삼성 공유의 content URI를 직접 받는 방식으로 변경한다. 신규 파일 탐지 조건을 느슨하게 하거나 기존 사진을 추측 삭제하지 않는다.

흐름: 지정 번호 대화 직접 열기 시도 → 헤더 번호 검증 후 공유 첨부 메뉴, 또는 검증된 사진 뷰어에서 앨범 → 전체 목록 1차 순회로 기간 대상 확정 → 처음으로 복귀 → 대상마다 번호/날짜 재검증 → 공유 → 전용 수신 activity에 전달된 원본 URI를 앱 전용 큐에 복사 → OneDrive 업로드 → 업로드 확인된 앱 임시 파일 제거 → 다음 항목. 처음 열었던 사진은 무조건 저장하지 않는다. 완료 시 대상/전송/기존/정리 건수가 일치하는지 확인한다.

공유 수신은 진행 중인 단일 사진 요청에만 허용하고 content URI 하나/image MIME/10MB/실제 헤더를 검증한다. 클립과 EXTRA_STREAM이 다르면 거절한다. 수신 Activity는 복사를 마칠 때까지 URI 권한을 유지하고, 복사 후 닫는다. 다른 소스/임의 비활성 공유는 읽거나 업로드하지 않는다. 공유 파일의 권한은 Android의 항목별 URI grant를 사용하며 광범위 미디어 읽기는 새 흐름에 필요 없다. 기존 레거시 큐도 앱 전용 파일만 처리하고 갤러리 삭제 경로는 제거한다. 광범위 미디어 읽기/관리 권한도 제거한다.

정확한 원본문자/RCS 첨부는 보존한다. 새 Download 사본을 만들지 않으므로 새 갤러리 삭제 요청도 하지 않는다. 과거 실패로 남은 Download 사진은 새 흐름에서 추측 삭제하지 않는다. 앱 임시 복사본만 업로드 확인 후 제거한다. 실패는 로컬 큐 유지 후 해당 번호/기간 재실행에서 재시도한다.

화면 현재 연도 제한, 모두 받은 사진이라는 실행 전 확인, 잠금 해제 필요는 유지한다. 대화/공유 메뉴 및 삼성 시스템 공유 UI의 실제 자동 탐색은 새 단말 검증 대상이며 모의 검증을 실기기 성공으로 주장하지 않는다. 임시 검사/네이티브 build+lint/기존 웹 build/독립 리뷰/같은 서명 검증 후 work에 커밋·Push한다.

독립 리뷰 대응: 호출 이름만 허용하지 않고 PackageManager preinstalled/updated system 플래그와 system 원본 제공자, API35 ComponentCaller URI 읽기 권한을 검증한다. 미완성 private 디렉터리는 격리 보존 후 동일 ID로 재접수한다. 원본 읽기는 별도 단일 작업자로 분리하고 취소/30초 제한을 두며, 제공자가 중지를 무시하면 추가 읽기를 막고 강제 중지를 안내한다. 늦은 읽기 결과는 큐나 네트워크에 등록하지 않는다. 같은 날짜/분/바이트 중복 첨부도 등장 순번으로 각각 보존한다. 새 URI 화면 기능은 Android15이상이며 일반 MMS Android13지원은 유지한다.
