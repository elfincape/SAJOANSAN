# 캡처 전 전체 주소 검증

사용자 지시: 기존 웹 기능에서 Excel 업로드 → 전체 주소 사전 검증 → 행·호차·역할·원문/수정 주소와 결과 확인 → 필요한 주소 수정·부분 재검증 → 확인된 코스만 순열 캡처 → 세로형 구간 Excel까지 완료한다. 원본을 추측 교정하거나 기존 성공 결과를 삭제하지 않는다. 기존 범위 내 구현·검증·배포는 승인됐다.

## 현재 상태와 선택

운영은 순열 캡처·구간 Excel·회차 분리·주소 후보 판정을 지원한다. 전체 주소 검증과 수정 UI는 없으며 지난 20건 통합은 수동 복구였다. 기존 화면 내 검증 단계를 채택한다. 캡처 도중의 첫 오류만 보는 방식은 전체 오류를 먼저 찾지 못하고, 별도 업무 화면은 요청한 일관된 흐름과 맞지 않는다.

## 구성

- 기존 naver_browser_jobs에 validation 종류와 선택적인 validation_job_id를 추가한다. 새 테이블·라이브러리는 만들지 않는다. 기존 소유자·센터 열람 권한, 취소, 큐, 상태, 워커를 재사용한다.
- 검증 RPC는 코스 구조를 확인하고 중복 주소를 한 번만 큐에 넣는다. 이전 같은 소유자/센터의 검증 중 정확히 같은 주소의 정상 결과를 재사용한다. 특정 주소 요청은 해당 주소만 다시 조회한다.
- 워커 검증은 기존 selectAddress·후보 판정·위치 토큰 검증을 사용한다. 정상, 여러 후보, 후보 없음, 네트워크/제공자 장애를 구별한다. 주소 오류는 다른 주소 검증을 계속하고, 제공자 장애는 기존 성공을 보존한 채 중단한다. 오류를 주소 미존재로 단정하지 않는다.
- 검증된 캡처 RPC는 서버에 저장된 검증 결과를 신뢰 원천으로 삼는다. 미확인 주소가 있는 새 코스는 큐에 넣지 않고 이유를 표시한다. 이전 같은 소유자/센터의 코스 중 실제 방문 주소와 회차가 같은 성공 결과만 보존한다. 변경된 코스의 과거 결과는 삭제하지 않는다.
- 검증 위치 토큰은 같은 소유자/센터의 검증 작업에서 워커가 읽고 다시 토큰/주소를 검사해 캐시로 사용한다. 클라이언트가 보낸 좌표·정상 플래그를 신뢰하지 않는다. 기존 직접 캡처 RPC도 호환되며 원래 주소 해석 방어를 유지한다.
- 업로드 원문과 원래 납품처 열 역할을 별도로 보존한다. 주소 수정은 명시적 입력·적용으로만 발생하고 같은 원문을 사용하는 방문에 함께 적용됨을 표시한다. 결과와 내보내기는 원문/수정·확인 주소를 구분한다.
- 기존 화면에 주소 검증 표를 추가한다. 중복 주소당 한 줄에 사용 위치(시트·행·호차·회차·역할), 원문, 검증할 주소, 정상/오류·확인 주소, 수정 적용·개별 재검증을 제공한다. 전체/문제 주소 필터와 진행 상태를 표시한다.
- 검증과 캡처의 실행 잠금·취소·센터 선택·새 파일 처리·이전 작업 복원을 연결한다. 기존 캡처 내보내기를 유지한다.

## 검증 기준

중간 빈 납품처의 원래 열 역할, 반복 주소 한 번 조회, 동일 주소 다수 사용처 수정, 원문 보존, 실패 한 주소만 재검증, 교차 소유자/센터 거부, 거짓 정상/좌표 입력 거부, 수정된 코스만 재계산, 이전 성공 보존, 회차 분리·취소·제공자 장애 보존을 검사한다. 실제 운영 버튼으로 업로드·전체 검증·수정·부분 재검증·소규모 경로 캡처·개별/일괄 Excel을 확인한다. 실제 두 미확인 차고지는 대체하지 않는다. 테스트용 수정은 별도 재현 파일에서만 한다.
