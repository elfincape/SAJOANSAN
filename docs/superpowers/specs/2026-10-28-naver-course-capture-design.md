# 네이버 코스별 실제 화면 캡처

관리허브의 기존 네이버 거리 화면에서 기존 엑셀의 시트·제목 행·호차·차고지·센터·납품처 열을 자동 탐색한다. 고정 양식은 필요하지 않으며 예시 엑셀은 선택 사항이다. 필요한 역할이 명확하면 점·장식·메모·참고 열은 자동 제외한다. 역할 충돌/누락 또는 실제 추가 납품처 주소 후보만 확인한다. 참고 열 UI는 기본 숨김, 검색 및 50개 단위로 표시해 대량 셀을 수동 분류하지 않게 한다.

차고지 한 값으로 일반 코스의 출발과 최종 복귀를 구성한다. 납품처 칸은 물리적인 왼쪽 열 순서대로 값이 있는 것만 사용한다. 빈 칸을 경유지나 누락으로 세지 않는다. 기존 별도 복귀 열은 실제 차고지 열이 있으면 참고로 제외한다.

## 회전별 경로와 출력
같은 호차명 끝의 1회/2회는 논리적 호차 그룹이다. **지도 요청과 캡처·출력은 각 회전별로 별도 수행한다.**
- 1회전: 차고지 → 센터 → 1회 납품처들 → 센터
- 2회전: 센터 → 2회 납품처들 → 차고지
행 순서와 무관하게 1회전, 2회전 순서로 각각 출력하며 원본 행 ID를 별도로 유지한다. 호차·회차가 이미지 파일명·화면·PDF 제목에 표시된다. 각 회전의 중간 방문지만 최대 5곳이며 두 회전 합계로 제한하지 않는다. 조회 단위 최대 100건, 원본 의미 있는 행 최대 200행/10MB. 첫 회전에는 센터 경유가 포함되고 둘째 회전의 센터는 출발지이므로 납품처가 하나면 경로점 3개도 허용한다.

개별 회전의 과다 경유지/주소 오류는 해당 회전의 오류다. 다른 정상 회전은 실행·출력 가능하며 성공 결과는 재시도 시 유지한다. 가져오기 오류도 작업 메타데이터에 보관해 복원 시 표시한다. 역할 매핑 자체가 불확실한 경우는 실행을 막는다. 짝 누락/회차 중복/명확히 다른 차고지·센터는 조용히 결합하지 않는다. 이전 통합 캡처는 이력으로 구분하고, 회차별 배치 출력에는 원본 엑셀 재등록이 필요하다.

## 비데이터 행
완전 공란·공백·빈 수식 결과·서식만 남은 행·순번/점/장식만 있는 행은 건너뛴다. 호차명이나 실제 주소 등 의미 있는 정보가 있는 불완전 코스는 유지하고 누락 필드를 구체적으로 알린다. 빈 행 뒤의 유효 행도 계속 읽고 건너뛴 행은 출력/오류 건수에 포함하지 않는다. 16~35행 공란 및 점 2만 셀/행을 변형 XLSX/도메인 검사로 재현한다.

## 실행 구조와 검증 범위
기존 naver_browser_jobs·Playwright 워커·비공개 Storage를 재사용한다. 큐 등록은 사용자와 센터 납품처 열람 권한을 확인하고, 이미지 조회는 소유자 및 센터 권한으로 보호한다. RPC 변경은 회전 메타데이터/출발·도착 규칙만 검증하며 EXECUTE 권한·Storage 정책을 재적용하지 않는다. PNG 개별/ZIP 일괄/PDF 회전당 한 페이지를 제공한다. 실제 네이버 거리우선 선택·방문지 목록·경로 결과 패널을 캡처하며 임의 이미지 재현이나 수학적 최단거리 보장을 하지 않는다.

현재 작업에는 실제 사용자 코스 원본 XLSX가 없어 사용자 보고(대-12호차 10·11행/합계 7, 16~35행 공란)를 재구성한 변형 파일로 검증한다. 실제 네이버 공개 주소 조회 및 서버 업로드와 모의 Supabase UI/출력 검증은 구분한다. Ego Lite는 이 클라우드에서 확인되지 않아 Playwright/Chromium을 사용한다.
