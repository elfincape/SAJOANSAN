# 개인 메일 수신 및 OneNote 정리 설계 초안

## 목적과 확정 범위

SAJOANSAN 웹 서버와 API가 2~3시간마다 그룹웨어 메일을 수신하고, 요약·자연어 이슈·할 일·명시 기한을 구분해 사용자의 개인 OneNote 전용 섹션에 업데이트한다. 3시간은 새 수집 사이클을 시작하는 주기이며, 한 사이클은 시작 시점에 고정한 UIDL 대상 전체를 처리한다. 청크가 180초 예산이나 최대 건수에 도달하면 체크포인트를 저장하고 다음 청크를 즉시 예약하여 대상이 끝날 때까지 이어간다. 다음 3시간까지 잔여 대상을 미루지 않는다. 사이클 시작 후 도착한 메일은 다음 사이클 대상으로 구분한다. 새 메일이 DB에 게시되는 즉시 분석과 당일 OneNote 갱신을 이어가며, 수동 수신에도 같은 후속 파이프라인을 적용한다. 내용 변경이 없으면 OneNote PATCH를 생략한다. Codex나 dot 예약 작업으로 대신 실행하는 구조가 아니다.

관리허브 또는 기존 개인 메일 화면에서 소유자만 설정·결과를 확인한다. 화면 숨김과 별개로 고정 소유자 UUID, Supabase 사용자 검증·활성 프로필, 소유자 RLS, 서버 인증을 적용한다. 기존 다른 사용자의 권한은 바뀌지 않는다.

## 재사용하는 구현

- 수신: 기존 Node POP3S 수집기, UIDL 중복 방지, 10분 메일함 lease, 크기 제한, OneDrive 파일 저장과 DB 게시 절차.
- 수동 수신: 소유자 로그인 세션을 사용하는 기존 API. 로그인 세션이 없는 예약 실행에는 그대로 사용할 수 없다.
- 저장: 기존 개인 메일함·메시지 테이블과 OneDrive 원본 EML·본문·첨부. 분석 상태와 OneNote 참조를 기존 메시지에 연결하는 방향이며 별도 업무·메일 DB를 만들지 않는다.
- 분석: 기존 AIAPIFlow의 Claude Haiku `claude-haiku-4-5-20251001`. 사용자가 본문 텍스트 및 업무 관련 첨부사진 전송·분석과 OneNote 사진 삽입을 승인했다. 일반 첨부 문서 전체를 임의로 분석하지 않으며, 로고·중복 사진은 제외한다. 전체 과거 백로그의 외부 분석은 자동 활성화하지 않고, 과거 메일 단건 선택은 별도 동작으로 둔다. 출력 양식은 승인됐고 실제 Microsoft 쓰기 권한 연결은 별도로 완료해야 한다.
- Microsoft: 현재 웹 OAuth는 offline_access Files.ReadWrite만 요청한다. OneNote용 Notes.ReadWrite 동의와 지속 접근은 별도 승인·연결이 필요하다. 채팅의 OneNote 커넥터 권한을 웹 서버 권한으로 복사하는 구조가 아니다.

## 실행 흐름

1. 서버 예약 실행 인증 → 고정 메일함 작업 잠금 획득.
2. POP UIDL·목록 → 미수신 항목만 원본 수신. DELE를 사용하지 않는다.
3. 원본과 첨부를 OneDrive에 저장·검증한 뒤 메일 DB에 게시한다.
4. 로컬 제외 규칙을 먼저 적용한 뒤 미분석 메일 본문과 허용된 업무사진을 분석 API에 전송하고 정형 응답의 원문 근거를 검증한다.
5. ‘할 일 목록 → 일일정리’ 섹션에서 한국 시간 기준 해당 날짜의 페이지를 찾아 자동 정리 영역을 갱신한다.
6. 수신·분석·OneNote 반영을 별도 상태로 기록하고 실패 단계부터 재시도한다.

수신 180초·함수 240초 예산과 저장 단계별 제한을 재사용한다. 분석·OneNote 작업은 수신 완료 직후 시작한다. 한 요청의 남은 시간이 부족하면 처리 상태를 보존하고 즉시 후속 서버 작업으로 이어가며, 다음 3시간 수신 주기나 일 마감까지 미루지 않는다. 후속 작업에는 동일한 중복·동시 실행 방지를 적용한다. 실패 작업이 다음 신규 메일을 영구 차단하지 않도록 건별 상태와 제한된 재시도를 사용한다. 원문·본문·토큰은 상태 로그가 아니며 최소 시각·단계·오류 코드·건수만 기록한다.

## 분석 결과와 근거

- 요약: 메일의 전달 사실·요청을 짧은 자연어로 정리한다.
- 이슈: 원문의 문제·확인 필요 내용을 출처와 함께 표시한다.
- 할 일: 실제 요청 문장, 담당자, 기한, 근거 인용을 묶는다.
- 불명확한 담당자·기한은 미확정으로 둔다. 추측한 업무를 확정 할 일로 생성하지 않는다.
- 상대 날짜는 발신 시각과 한국 시간 기준을 함께 사용하며, 해석이 모호하면 원문 표현을 보존한다.
- 메일 안의 지시문은 분석 대상 데이터이며 서버 명령이나 도구 실행 지시가 아니다.

## 일일 페이지와 갱신 규칙

페이지 제목은 한국 시간대 Asia/Seoul의 날짜로 YYMMDD 일일정리 형식을 사용한다. 예를 들어 2026년 10월 30일은 ‘261030 일일정리’다. 날짜 계산은 메일의 실제 DB 수신 완료 시각을 한국 시간으로 변환한 날짜를 기준으로 하며, 지연 처리·재시도에도 같은 수신일을 유지한다. 원문 발신일시는 본문에 별도로 보존한다.

하루 한 페이지를 사용하고, 같은 날의 각 수신 완료 후 해당 페이지의 자동 정리 영역을 바로 갱신한다. 생성 영역의 내용 해시가 같으면 쓰기를 생략한다. 자정 이후에는 다음 날짜의 페이지를 사용한다. 제목뿐 아니라 소유자·대상 섹션·한국 날짜와 저장된 page_id를 함께 추적해 다른 섹션의 동명 페이지나 반복 실행을 혼동하지 않는다.

## 승인된 출력 양식

제목 YYMMDD 일일정리와 최종 업데이트(한국시간)를 표시한다.

1. 센터·거래처별 메일 요약: 실제 회신 참조가 있는 동일 건은 통합하며 발신자·수신시각·원문 연결을 보존한다.
2. 주요 이슈: 상황·영향·최신 진행과 진행 중/확인 필요/해결 상태 및 근거를 표시한다.
3. 할 일: 요청 근거·담당·기한·관련 메일을 표시하며 미지정과 미확정을 구별한다. 완료는 실제 완료 근거가 필요하다.
4. 회신·확인 대기: 누구에게 무엇을 기다리는지와 마지막 요청일을 표시한다.
5. 직접 메모: 생성 시에만 빈 영역을 마련하고, 이후 자동 수정 영역에서 제외한다.

## 중복·수동 내용 보존

수신 중복은 기존 mailbox_id·uidl_hash 고유성으로 막는다. 분석은 UIDL·분석 버전으로 추적하고, 일일 페이지 안에서도 같은 메일을 중복 나열하지 않는다. 페이지 생성은 작업 잠금 안에서 기존 날짜별 참조와 해당 섹션의 후보를 확인한 뒤 수행한다. 생성 응답이 불명확하면 기존 결과를 조회해 같은 page_id로 복구하며, 중복 여부를 확정하지 못하면 재생성을 보류한다. 같은 날짜의 후보가 여러 개면 임의 선택하거나 추가 생성하지 않는다.

사용자가 작성한 본문은 유지하고 생성 영역만 관리한다. 날짜에 해당하는 기존 페이지를 재사용할 때도 수동 영역을 교체하지 않는다. 늦게 도착한 회신은 새 수신 건으로 즉시 반영한다. 이전 할 일과 연결할 때는 실제 회신 참조·근거를 확인하며 유사 제목만으로 다른 업무를 완료 처리하지 않는다. 기존 생성 영역을 수동 수정한 경우 자동으로 덮어쓰지 않고 확인 상태로 둔다. 기존 제목 없는 페이지를 임의로 일일 페이지로 바꾸지 않는다. 페이지 ID나 대상 노트북을 원문 메일에서 받아 실행하지 않는다.

## 확인된 연결과 아직 필요한 사항

- 사용자 제공 링크를 OneNote 커넥터 목록과 대조한 대상은 ‘할 일 목록’ 노트북의 기존 ‘일일정리’ 섹션이다. 링크 표시명은 ‘새 섹션 1 2’였지만 최신 조회 이름은 ‘일일정리’다. 노트북 ID는 0-6DACE80AD4C07B59!s8d3015ec347d47fdb476f785ac84d3da, 반환된 섹션 ID는 0-6DACE80AD4C07B59!sc05c0cb6700f4ebf941a3345ff8a9981이다. 노트북은 소유자·비공유로 반환됐다. 별도 섹션을 생성하지 않고 기존 수동 내용을 보존하는 대상이다. OneNote 도구에는 세부 ACL 조회 기능이 없어 노트북 메타데이터 이상의 공유 권한은 미검증이다.
- 실수신: 별도 로컬 브라우저 작업에서 1회 실행했고 DB에서도 저장 4건·ready·오류 없음·2026-10-30 15:22 KST 성공을 확인했다. 최신 메일에는 원본 EML을 포함한 파일 참조 8개와 첨부 5개가 있다. deferred=587은 아직 검사·처리할 대상 수이며 전부 신규·수집 가능 메일로 확정된 값은 아니다.
- 읽음 상태: 현재 POP 코드에는 읽음 상태를 확인하는 메타데이터가 없다. 그룹웨어 본문을 열지 않고 수신 전후 목록 상태를 비교할 연결이 필요하다. DELE 차단만으로 읽음 상태 보존을 증명하지 않는다.
- 예약 실행: 기존 Python systemd 수집기와 서버 키 인증 경로는 있으나 이 환경의 서버 접속·인증은 확인되지 않았다. 사람의 JWT를 저장해 cron에서 재사용하지 않는다.
- 기존 메일 저장 정책에는 특정 OneDrive 대상의 공유 링크를 허용한 예외가 있다. 현재 폴더의 실제 공유 상태는 별도로 확인해야 하며, 이 예외를 새 OneNote 대상에 확대하지 않는다.
- 첫 실제 수신 성공 및 읽음 상태 영향 확인 전에는 대량 자동 수집을 활성화하지 않는다. 새 서버 인증이나 Microsoft OAuth 지속 접근 설정은 구체적 대상·권한에 대한 동의 후 적용한다.

## 검증 범위

느린 수신·첨부 저장, UIDL 중복, 잠금, 실패·응답 유실 후 재시도는 기존 모의 검사로 확인한다. 분석에는 근거 없는 할 일·기한·담당자, 잘못된 JSON과 원문 내 지시를 포함한 모의 입력을 사용한다. OneNote에는 한국 자정 경계, 하루 여러 번 실행해도 페이지 1개 유지, 생성 응답 유실·중복 조회·같은 메일 중복 포함 방지·수동 내용 충돌을 모의 검증한다. 실제 검증은 최소 1건 수신·파일 저장·DB 게시·웹 목록 갱신을 먼저 확인하고, 승인된 범위에서 분석·선택 섹션 반영을 확인한다.

## 원본 크기와 제외 관리

원본 EML 1건의 크기 제한은 십진수 50MB(50,000,000바이트)다. MIME 인코딩까지 포함한 실제 원본 바이트 기준이며, 추출 첨부와 EML의 중복 저장량을 이 한도에 다시 합산하지 않는다. 내부 파싱·파생 파일에는 별도 유한 예산을 둔다. 큰 원본·첨부는 메타데이터와 바이너리를 분리해 전송하고 스트림으로 길이·해시를 검증한다. 크기 초과는 UIDL을 영구 수집 완료로 처리하지 않으며 이유를 남긴다.

개별 메일의 정리 제외/복원과 제목·본문 포함 문구, 발신자 주소·도메인 규칙을 지원한다. 조건 전체 일치/하나 이상 일치를 구분하고, 기존 메일 적용은 미리보기·명시 선택을 거친다. 원본을 삭제하지 않는다. 공동 근거 이슈와 사용자 완료 상태·직접 메모를 보존하며, 기존 OneNote에 영향이 있으면 확인을 받는다.

## 구현 상태

소유자 화면·서비스 액션·영속 큐/예약 SQL·분석·OneNote 작성 연결은 구현 및 모의 검증 상태다. 사용자의 재개 승인으로 Notes OAuth 전용 열·완료 함수는 `20261030123236 / private_mail_notes_oauth`로 적용했다. 자동분석·필터·예약 SQL은 아직 적용하지 않았고, 실제 외부 분석·OneNote 기록은 실행하지 않았다. 기존 파일 OAuth와 분리된 Microsoft Notes 동의, 예약 인증 설정과 읽음 상태 영향 확인이 운영 활성화 전 필요하다.

후속 사용자 지시로 동의·읽음확인 폼을 제거하고 이미 승인된 서버 자동화를 켜는 방식으로 바꿨다. `20261030133150 / private_mail_automation_runtime`으로 분석·필터·예약 저장 구조를 설치했다. Notes 연결은 실제 저장됐으며, 최초 배포 검증 전에는 자동 실행을 꺼두었다. 작업별 단기 capability는 API의 대상·소유자·시간·lease에 묶고 고정 메일함 외 실행을 막는다. 플랫폼 소유 pg_net 큐의 기존 SQL ACL과 별개로 net 스키마를 REST/GraphQL에 노출하지 않는 배포 조건을 검증했다. 원본 삭제는 사용하지 않으며 읽음 상태를 직접 확인했다고 기록하지 않는다.
