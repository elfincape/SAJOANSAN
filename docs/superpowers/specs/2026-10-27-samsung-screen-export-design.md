# 삼성 메시지 화면 사진 저장

MMS provider 0건인 삼성 파일전송 사진을 사용자가 제공한 실제 UI 구조로 수집한다. viewer_title(번호), viewer_sub_title(날짜), album, gallery_item_image(날짜), save와 Download/ 저장은 단말에서 확인됐다. 코드는 원래 MMS 기능을 유지하고 같은 문자 앱에 명시적 화면 수집 버튼을 추가한다.

사용자가 직접 선택한 번호의 사진 뷰어에서 시작한다. 공유 첨부 목록을 처음으로 이동한 뒤 기간 후보를 열어 번호와 뷰어 날짜를 재확인하고 저장한다. 제목의 번호가 실제 발신자를 뜻하는지는 미검증이므로, 사용자 확인 없이 받은 사진만이라는 주장을 하지 않는다. 화면 모드는 해당 목록 사진이 모두 상대방에게 받은 것임을 사용자가 확인한 경우에만 시작한다. 직접 보낸 사진이 섞여 있으면 지원하지 않고 원인 확인을 이어간다.

연도 없는 뷰어 날짜는 올해 한국 시간 연도로 해석하며 화면 모드는 올해 안의 기간만 지원한다. 명시적인 다른 연도 뷰어는 제외한다. 이미지 파일명 날짜는 사용하지 않는다. RecyclerView collection row/column으로 실행 중 중복/겹침을 구분하고 위치 정보를 얻지 못하면 미완료로 중단한다. 동일 날짜·분·이미지 해시의 재실행은 같은 접수 ID를 사용한다. 목록 변경·잠금·예상치 않은 화면·동시 다운로드 의심 시 중단한다.

새 Download/ 이미지의 MediaStore owner가 삼성 메시지이고 사전 snapshot ID와 미디어 generation 경계 이후에 새로 삽입된 한 장일 때만 실제 바이트를 읽는다. 기존 OneDrive 업로드/재시도/취소를 재사용하고 원격 JSON은 추가하지 않는다. 원본문자·RCS 첨부는 삭제하지 않는다. 전송 후 새 갤러리 저장본은 계정·원격파일·로컬ID/경로/해시 재검증과 MANAGE_MEDIA 허용이 있을 때만 시스템 삭제 요청한다. 검사와 비동기 삭제의 TOCTOU 한계는 기존 정리 방식과 같다. 삭제 권한 없으면 사본을 남긴다.

접근성은 삼성 메시지 패키지만, 추가 미디어 권한은 새 저장본 확인에 사용한다. 화면 켜짐/잠금 해제가 필요하다. 실제 새 APK의 전체 자동 수집·스크롤·삭제는 아직 실기기 미검증이다. 저장소 외 임시 검증/Android build/lint/기존 웹 build 후 커밋·Push한다.

사용자가 대화의 사진이 모두 상대방에게 받은 사진임을 직접 확인했다. 앱에서도 매 실행 확인을 요구한다. 독립 리뷰의 기존/미완료 파일 오인, 중간 스크롤 거부를 끝으로 오인, 미인식 설명 누락을 보완하고 임시 회귀로 확인했다. 표시 연도 제한/분 단위 시각/비공식 UI와 미디어 연결 한계를 명시한다.
