# 카카오톡 수집 → OneDrive 직접 저장

## 승인된 범위

사용자는 2026-10-22에 작업 범위를 ‘카카오톡 수집 → OneDrive 저장’으로 한정하고 직접 구현하도록 요청했다. 관리허브 활용·업무 생성·AI 분석은 별도 개발이다. 기존 React 앱·Supabase·Vercel·원본 파일과 서버 인증은 변경하지 않는다.

법인 갤럭시 점프3(One UI 8.0)에 설치하는 별도 안드로이드 앱을 `android/kakao-collector`에 둔다. 상시 USB·PC 없이 폰에서 사진과 대화정보를 Microsoft Graph로 전송한다. UI·네트워크는 Android 기본 API를 쓰며 중복 라이브러리를 추가하지 않는다.

## 확인된 사실

실제 폰의 UIAutomator에서 사진·묶음사진과 저장 버튼이 노출됐다. ADB로 사진 열기·묶음 전체 저장을 조작해 JPG 세 개를 확보했고 사용자가 정상 열람을 확인했다. 이는 ADB 실증이며 접근성 서비스로 같은 동작이 성공했다는 증거는 아니다. 저장 파일이 송신자의 촬영 원본과 같은지도 검증되지 않았다.

## 구현

- 정확한 대화방 이름 허용 목록을 사용한다. 동일 이름 방을 구분하는 기능은 없으므로 동일 이름 방은 등록하지 않는다. 알림의 방 이름을 확인한 뒤에도 카카오톡 상단 제목이 일치해야 조작한다.
- 지정 방의 텍스트 알림은 메시지 목록·게시 시각과 함께 `kind: notification`인 내부 접수로도 보관하고 원격에는 TXT만 올린다. 알림에서 제공한 텍스트만이며 전체 대화 복원은 아니다.
- 새 알림을 계기로 카카오톡을 열거나, 사용자가 현재 열린 방 수집을 요청한다. 화면에 보이는 사진을 요소 기반으로 찾고 단일/묶음 저장을 실행한다. 좌표는 매번 현재 요소 bounds에서 계산한다.
- 저장 전후 `Pictures/KakaoTalk/`의 MediaStore 항목을 비교한다. 예상 사진 수와 실제 생성 수가 일치하고 파일 크기가 안정된 경우 앱 내부 큐로 복사한다. 다른 앱 사진과 혼동될 수 있는 개수 불일치는 자동 연결하지 않는다.
- JPEG/PNG/WEBP만 허용하며 파일 시그니처·MIME·사진당 10MB를 검사한다. 묶음은 최대 30장이다. 실패는 상태에 표시하고 원래 카카오톡 저장 사진은 삭제하지 않는다.
- 사진과 주변 화면 텍스트·알림 정보를 접수별 UUID로 보관한다. 화면 텍스트는 주변 문맥이고 정확한 사진 발신자/개별 메시지 연결을 보장하지 않는다고 JSON에 표시한다. 관찰 시각과 알림 게시 시각을 구분한다.
- Microsoft 개인 계정용 공용 클라이언트 device code OAuth를 사용한다. 사용자가 등록한 클라이언트 ID만 입력하고 앱 비밀 키를 사용하지 않는다. 최상위 일반 폴더 저장에 필요한 `offline_access Files.ReadWrite`를 요청한다. 앱의 실제 업로드 경로는 `이안카카오` 아래로 고정한다.
- access/refresh token은 Android Keystore AES-GCM으로 암호화해 앱 전용 저장소에 보관한다. 백업·평문 통신을 차단한다. 기존 관리허브의 OneDrive 서버 토큰은 사용하지 않는다.
- 저장 위치는 OneDrive 최상위의 `이안카카오/<대화방 이름>/`이다. 없는 폴더는 생성하고 기존 폴더는 재사용한다. 파일명은 한국 시간의 수집 시각(밀리초 포함), 전체 접수 UUID, 사진 순번으로 만든다. 이미지는 저장된 바이트를 변경하지 않고 올리며 대화는 같은 시각·UUID의 `_대화.txt`로 올린다. v0.2.2부터 원격 JSON은 생성하지 않고 내부 접수 정보만 앱 전용 저장소에서 재시도에 사용한다. 데이터 분석·가공은 별도 개발 범위다. OneDrive 금지 문자·예약어·긴 방 이름은 정리하고 해시로 구별한다. 재시도에도 이름은 변하지 않는다. 계정의 drive ID를 접수에 묶어 다른 계정으로 잘못 전송하지 않는다.
- 30초 간격으로 대기 건을 순차 전송한다. 같은 UUID와 파일명으로 재시도한다. 완료 표시 전에는 로컬 파일을 유지한다. 완료 후 앱 내부 사진 사본만 정리하며 카카오톡 저장 사진과 접수 JSON은 유지한다.
- 시작·중지·대기 건수·오류를 앱에 표시한다. 실행 중 알림에 중지 동작을 제공한다. 중지는 새로운 수집·다음 업로드를 막지만 이미 전송 중인 HTTP 요청까지 취소된다고 보장하지 않는다.

## 명시적 한계와 실기기 검증

이 버전은 폰 단독 수집 검증용이다. 과거 대화 자동 스크롤, 전체 방 주기 순회, 화면 밖 사진 회수, 기기 재부팅 후 자동 시작, 알림 누락 복구, 정확한 개별 사진 발신자 연결은 구현하지 않는다. 알림 대기열은 메모리이며 서비스 종료 시 사라질 수 있다. 이미 앱 내부 큐에 기록된 사진의 업로드는 다시 시작하면 재개한다. 화면 문맥이 바뀌면 같은 사진을 다시 수집할 수 있고, 같은 문맥의 반복 요청을 구분하지 못할 수 있다. 운영 무누락 수집으로 보고하지 않는다.

전용폰은 충전·화면 켜짐·잠금 해제가 필요하다. One UI의 접근성 제한 설정, 전체 사진 접근, 알림 접근, 배터리 제한, 백그라운드 방 열기를 실제 설치 후 확인해야 한다. 재부팅 후에는 사용자가 수집을 다시 시작한다.

Microsoft 앱 등록과 이전 버전의 개인 OneDrive 알림 JSON 저장은 사용자가 확인했다. 새 버전의 사진·TXT 직접 업로드는 실제 단말에서 확인이 필요하다. v0.2.0에서 일반 폴더 권한으로 전환했으므로 이전 AppFolder 토큰은 전송 전에 거절하고 재로그인을 요구한다. 기존 원격 파일은 이동·삭제하지 않는다. APK 빌드·로컬 규칙 검증과 실제 로그인·사진 업로드 검증을 분리한다. 실기기 검증 전에는 배포 준비 완료나 운영 성공을 주장하지 않는다.

## 검사

새 테스트 파일은 저장소에 추가하지 않는다. 저장소 밖 Java assert 검사로 묶음 개수·방 정확 일치·파일명·수집 키를 확인하고 Android assemble/lint를 수행한다. 기존 웹은 `npm --prefix app run build`로 확인한다. 웹 화면을 변경하지 않으므로 관련 브라우저 동작 변경은 없다.

## v0.2.2 실기기 증거 반영

사용자는 OneDrive에 JSON만 저장되고 사진이 없음을 확인했다. 실제 UI dump에서 방 제목은 `com.kakao.talk:id/toolbar_default_title_text`의 빈 text와 nonempty content-desc로 제공됐다. 기존 제목 ID·text 전용 판정이 이 구조를 거부해 방 이동 이후 진행을 막는 코드 결함을 확인하고 수정했다. 제목의 위치·카카오톡 패키지·허용 목록 판정은 유지한다. 사진 단계와 업로드 상태를 별도로 보존해 텍스트 성공이 사진 실패를 가리지 않게 한다. 새 이미지·TXT 저장은 모의 업로드와 빌드 검증을 하고, 실제 폰 사진 업로드는 여전히 별도 확인한다.


## v0.2.3 사용자 확정 범위

폰 UI 조작으로 사진을 저장하는 방식을 유지하고 OneDrive 업로드 확인 후 폰 저장본을 정리한다. 화면 켜짐·잠금 해제는 여전히 필요하다. MANAGE_MEDIA 특별 접근을 사용자가 한 번 허용하며 시스템 MediaStore 삭제 요청을 사용한다. 새 접수의 원본 ID/경로/수정 정보/해시와 원격 파일 계정/존재/크기를 확인한다. 권한·검증 실패 시 원본을 유지하고 이전 접수·기존 갤러리 파일은 추정 삭제하지 않는다. 검사와 비동기 삭제 사이의 변경을 원자적으로 보장하지 않으므로 정리 대기 사진을 편집하지 않는다. 실기기 자동 저장·삭제는 별도 검증 대상이다.
