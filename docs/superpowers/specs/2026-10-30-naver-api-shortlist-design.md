# API 거리 후보 3개와 웹 검증

사용자 승인: 기존 API 설정을 재사용해 구현·테스트한다. 새 키·가입·지속 접근 설정과 요금 범위 밖 호출은 승인 없이 실행하지 않는다. 주소 사전검증 운영 배포는 별도 완료 범위로 보존한다.

- 주소 검증 작업의 서버 저장 좌표만 API에 사용한다. 순열의 고정 차고지·센터·복귀지와 회전 분리를 유지한다.
- 방향별 API 거리 행렬을 완성한 뒤 모든 납품 순열의 센터→납품처들 구간 합만 채점한다. 차고지→센터와 마지막 납품처→복귀지는 API 요청과 점수에서 제외한다. 후보의 전체 동선은 보존하며 웹에서 출발·복귀를 포함한 총거리로 비교한다. 고유 납품 4/5곳은 기본 16/25회 방향별 조회다. 실제 API 옵션 3개의 원본 m 중 최솟값을 쓰며 도시명·직선거리·시간으로 거르지 않는다.
- 상위 3개 방문 순서만 기존 웹 캡처 엔진에 전달한다. 결과는 후보 중 웹 최단이며 전체 웹 전역 최단으로 표시하지 않는다. 기존 전순열 모드는 유지한다.
- 기존 naver-relations Edge Function의 자격증명, API 작업/잠금/월 한도/500ms 지연을 재사용한다. 새 인증정보를 브라우저·GitHub 실행기로 복사하지 않는다.
- API 작업은 같은 사용자·센터의 완료된 주소 검증 작업만 읽고 서버 측 후보/행렬 증거를 보관한다. 큐 RPC가 그 작업을 검증하여 캡처에 연결한다. 클라이언트 후보·좌표는 신뢰하지 않는다.
- 방향 좌표·API 버전·옵션·차량·연료를 캐시 키에 넣고 30분 만료를 적용한다. 실패·누락·만료 행렬은 최종 후보로 확정하지 않는다.
- 웹 경유지 5개 한도를 유지한다. 단일/1회전 센터+납품은 최대 납품 4곳, 2회전 납품 5곳이다. API의 더 큰 한도로 웹 제한을 우회하지 않는다.
- 최종 Excel 구간은 선택된 웹 경로 응답에서만 가져오며 API 구간 합을 실제 승자 구간으로 내보내지 않는다.
- 기존 성공 결과/주소 원문/원본 파일과 다른 기능 변경은 보존한다. 새 API 실행의 운영 배포는 구현·검증·요금 확인 결과를 먼저 보고한다.
