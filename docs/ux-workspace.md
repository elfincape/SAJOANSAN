# 공통 업무 UI·UX 개선

2026-10-22. React + TypeScript 앱의 탐색·편집 피드백·권한 노출·반응형·모션을 개선했습니다. 배차 계산, 엑셀 양식, Supabase 쿼리와 서버 권한 정책은 유지합니다.

## 적용 범위와 사용법

- 사이드바의 영역은 옅게, 현재 페이지는 대비가 높은 배경·굵은 글자·점으로 구분합니다. 하단에는 현재 화면·센터·역할을 표시합니다. 포털의 세부 화면 이름은 헤더와 브라우저 제목에도 반영하며 이동한 view를 URL에 유지합니다.
- 헤더의 검색 버튼 또는 `Ctrl/⌘ K`로 KBAR 빠른 이동을 엽니다. 한국어 화면 이름·설명 검색, 방향키 선택, Enter 이동, Esc 닫기와 이전 포커스 복귀를 지원합니다. 팝업·드로어가 열려 있거나 요청 처리 중이면 단축키로 다른 화면을 열지 않습니다.
- 허브 카드·하위 메뉴·커맨드 목록은 동일한 역할·센터·기능 표시·열람 권한 판정을 사용합니다. 포털의 메뉴·검색·현재 제목도 공통 화면 등록부를 사용하며 접근 불가능한 그룹은 숨깁니다. 기능 표시 설정이 변경되면 열린 화면의 검색 목록도 갱신됩니다.
- 설정에는 해당 센터의 사용 가능·열람 전용·열람 불가·다른 센터 기능 상태를 표시합니다. 페이지별 권한 편집에는 해당 권한을 사용하는 화면 이름을 표시하고 그 이름으로도 검색할 수 있습니다.
- 기사·차량·운수사·납품처 편집에는 신규 입력 안내, 미저장 변경, 저장 중, 저장된 내용, 열람 전용 상태를 표시합니다. 저장 중과 열람 전용에서는 폼을 비활성화합니다. 미저장 상태의 목록 선택·신규 작성·센터 전환·일반 링크·커맨드 이동·새로고침에는 입력 유실 방지를 적용합니다. 저장 후 목록 갱신은 기존 동작을 유지합니다.
- 업무 포털 상세에는 입력 후 저장·업무 완료 중 다음 동작을 안내합니다. 오류는 즉시 읽히는 알림으로 표시합니다. 공통 오류 토스트는 직접 닫을 때까지 유지하고 같은 오류는 중복 적재하지 않습니다. 일반 결과는 6.5초, 확인 안내는 12초 유지하며 마우스·포커스가 머무르면 자동 닫기를 멈춥니다.
- 공통 모달은 native dialog를 사용해 배경 조작 차단·Tab 포커스 제한·Esc·포커스 복귀를 지원합니다. 창 안에서 시작한 텍스트 드래그가 배경에서 끝나도 닫히지 않습니다. 삭제 확인에는 별도 이름을 부여합니다.

## 시각·동작 기준

- 기존 의미별 테마 토큰과 텍스트 선택 대비를 유지합니다. 글래스는 오버레이·사용자 메뉴·슬라이드오버 헤더에 제한하고 입력·표 본문은 불투명 표면을 사용합니다. 뉴모피즘은 검색 진입 버튼의 얕은 표면 표현으로 제한합니다.
- 관리 허브는 업무 목적별 분류와 검색으로 허용된 도구를 한 번씩 표시합니다. 임의 추천·센터 및 역할 요약 벤토는 제거했습니다.
- 본문은 Pretendard, 시간·측정값·숫자 전용 표시와 단축키는 자체 제공 IBM Plex Mono를 사용합니다. 글꼴을 외부 CDN에서 가져오지 않습니다.
- 지원 브라우저에서는 문서 이동 시 짧은 View Transition을 사용합니다. 초기 HTML에서 활성화해 지연 로딩 중 전환 설정이 바뀌지 않도록 합니다. 미지원 브라우저는 기존 링크 이동을 사용합니다. 포털 내부 화면 제목, 팝업, 드로어, 드롭다운에는 짧은 상태 전환을 적용합니다.
- 모션 감소 사용자는 공간 이동·회전·문서 전환 애니메이션 없이 같은 업무를 처리할 수 있습니다. Lenis의 기존 예외와 입력·표·모달의 기본 스크롤을 유지합니다.
- 모바일 검색창은 독립된 줄을 사용하며 기준정보 표는 내부에서 가로 스크롤합니다. 헤더·주요 편집 동작은 44px 터치 높이를 적용하고 좁은 헤더의 빠른 이동은 아이콘으로 줄입니다.
- 기존 AG Grid를 재사용하고 방향키 셀 이동·포커스 대비·정렬/필터 안내를 추가했습니다. TanStack Table을 중복 설치하거나 기존 배차표를 다시 구현하지 않았습니다.

## 기능 등록 방법

`app/src/domain/feature-catalog.ts`에 관리 기능을 등록하면 설정·허브·사이드바·커맨드와 관련 권한의 적용 화면 목록에 반영됩니다. `portal-navigation.ts`의 포털 화면은 메뉴·커맨드·현재 제목·관련 권한 목록에 반영됩니다. 새로운 권한 resource 자체를 만드는 경우 서버 정책과 RPC 등록은 별도 작업이며, 미등록 권한을 브라우저에서 임의로 허용하지 않습니다. 기능 표시 설정은 기존과 같이 계정별 현재 브라우저의 설정이며 다른 사용자의 권한을 바꾸지 않습니다.

## 검증과 변경 리뷰

기준 커밋은 `780195a`입니다. 공통 셸·모달·알림·테마는 33개 진입 화면에 영향을 주므로 화면별 시각 검사와 실제 키보드 동작을 함께 확인했습니다. `featureAccessible`은 허브·관리 셸·포털 셸 세 곳에서 공유하고, 편집 가드는 기준정보 네 화면에 적용합니다. 공통 모달을 사용하는 7개 컴포넌트·페이지를 검토하고 삭제·편집·실패 재시도를 확인했습니다.

- TypeScript/Vite 빌드 통과. 기존 Excel/PDF/AG Grid 대형 번들 경고는 남아 있으며 새 커맨드 번들은 gzip 약 38KB입니다.
- 33개 진입 화면 × 두 테마 × 데스크톱 1440px/모바일 390px = 132개 화면. 검사 대상 텍스트의 기본·hover 대비 미달, 페이지 가로 넘침, 브라우저 예외 없음.
- 포털 내부 15개 화면 × 두 테마, 선택·텍스트 드래그·Tab·필터·팝업·파일 dragover 등 별도 18개 상태 확인. 글래스의 `color(srgb)` 표기도 알파 합성해 검사했습니다.
- KBAR 한국어 검색·키보드 이동·모바일·모션 감소·포커스 복귀, 기능 설정 실시간 반영, 조회 전용 폼, 권한 없는 메뉴/커맨드 숨김과 직접 주소 차단 확인.
- 다섯 기준정보의 실패 후 입력 보존·재시도·센터 범위 삭제, AG Grid 필터·편집·삭제 확인, 설정 저장·탭 동기화, 페이지 권한의 역할/센터/자료 범위와 버전 기반 저장 확인.
- 포털의 저장 재시도 request ID, 숫자 0·false·알 수 없는 필드 보존, 담당자 변경 초안, 한국 시간 마감 변경, 완료·재개·휴지통 흐름 확인.
- 새 공통 UI의 Impeccable 검사와 변경 코드 검토에서 추가 보안 결함을 발견하지 않았습니다. 기존 `permissionAllowed`·서버 권한 정책·업무 저장 함수는 수정하지 않았고, UI 숨김을 서버 권한 검증의 대체로 사용하지 않습니다.

변경 리뷰에서 새로 확인된 Critical/High/Medium/Low 보안 결함은 각 0건입니다. 입력 유실 방지와 탐색 상태 변경은 중간 수준의 회귀 위험으로 분류해 위 모의 검사를 적용했습니다. 서버 인증·RLS의 전체 재감사나 실사용 계정별 운영 쓰기 검증은 이번 검토 범위에 포함하지 않습니다. 배포 판단은 빌드·기능 회귀·브라우저 검증 통과를 기준으로 합니다.

검증 자료와 임시 스크립트는 저장소 밖에 보관합니다. 로그인 이후 검증은 모의 인증·업무 응답으로 수행했으며 운영 DB·실제 AI 요청·메일 수집을 변경하지 않았습니다. 텍스트 대비 검사와 Chromium의 반응형 검사는 모든 사용자 데이터·실제 휴대전화·이미지 안의 문자에 대한 접근성 인증을 뜻하지 않습니다.

후속 디자인·업무 조작 확장의 적용 위치와 제외 요소는 [업무 화면 디자인·조작 확장](ux-workbench.md)을 참고하세요.
