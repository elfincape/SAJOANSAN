# 안산 1탑2실 사진 행 밀림 조사

조사일: 2026-11-01. 신고 내용은 다운로드한 엑셀에서 약 30행부터 사진이 한 줄씩 밀린다는 것이다. 신고 당시 원본·결과 파일은 제공되지 않았다. 후속 캡처와 같은 오배치가 있는 수신 엑셀을 로컬에서 발견해 추가 대조했다. 웹에 올린 입력 원본인지, 다운로드 후 저장한 파일인지는 확인되지 않았다. 아래 재현된 결함을 신고 사례의 확정 원인으로 간주하지 않는다.

## 처리 경로

`OneTopWork` → `matchOneTopWorkbook` → H열 차량 매칭 → Q열 영수증·P열 보조사진 삽입 → `oneTopOutputBlob` → ExcelJS 저장 → 다운로드.

사진과 날짜·온도는 동일한 `target.row`를 사용한다. 사진은 0 기반 앵커의 시작을 `row - 1`, 끝을 `row`로 기록한다. 파일 저장 후 drawing XML과 다시 읽은 앵커를 대조했으며, 행을 삽입하거나 목록 순번으로 좌표를 계산하는 경로는 없었다.

## 재현된 결함과 수정

### 1. 같은 완성 파일을 재처리하면 동일 사진이 다른 행에 추가됨

기존 중복 검사는 이번 실행에서 추가한 사진만 비교했다. 기존 Q열 이미지가 있는 완성 파일을 다시 업로드하면 기존 행은 점유된 것으로 판단하고 같은 차량의 다음 빈 행을 선택했다.

기본 양식과 가상 사진 57장으로 결과를 생성한 뒤 같은 결과·사진을 재입력했을 때, 수정 전에는 다음 4건이 새로 삽입됐다.

| 사진 차량 | 재입력 시 잘못 추가된 행 |
| --- | --- |
| 경기94사5994 | 65 |
| 서울80바6357 | 51의 경기90아6357 |
| 경기94아9619 | 63 |
| 경기90자9936 | 57 — 기존 56행 바로 다음 |

수정: 엑셀 삽입용으로 압축한 사진과 기존 Q열 이미지의 실제 바이트를 SHA-256으로 비교한다. ExcelJS가 읽은 `buffer`와 새 사진의 `base64`를 동일한 바이트 형식으로 처리한다. 같은 사진이 있으면 다른 빈 행에 재삽입하지 않는다. P열 보조사진은 일반적인 P셀 앵커에서 이 비교에 포함되지 않는다.

### 2. 전체 차량번호가 있어도 끝 네 자리로 서로 다른 차량을 혼동

기본 양식의 38행 `서울80바6357`, 51행 `경기90아6357`이 같은 키로 묶였다. 전체 번호가 `경기90아6357`인 사진도 수정 전에는 빈 38행에 들어갈 수 있었다.

수정: 전체 번호가 있으면 해당 번호와 일치하는 행만 선택한다. 지역명을 생략한 `90아6357`도 일치하는 번호가 명확할 때 허용한다. 네 자리 `6357`만 있고 서로 다른 차량이 여러 개면 임의로 고르지 않고 확인 대상으로 남긴다. 같은 차량의 여러 작업 행과 서로 다른 차량의 충돌은 구분한다.

## 30행 부근의 양식 차이

실제 기본 경로 `/templates/one-top-two-room-template.xlsx`는 65행이며 5~65행이 작업 행이다. 기본 작업 행은 모두 99.75pt이고 숨김·작업 영역 병합·기존 사진이 없다. 병합 15개는 3~4행 헤더에 있다.

별도 `/assets/templates/one-top-two-room-template.xlsx`는 66행이며 32행에 `경기82바2906`이 추가돼 있다. 두 파일은 32행 이후 차량 행 번호가 다르다. 단, 매칭 코드는 선택된 파일 자체의 H열 행을 사용하므로 두 양식이 존재한다는 사실만으로 다운로드 중 사진 좌표가 바뀐다고 단정할 수 없다. 양식은 이 조사에서 변경하지 않았다.

## 검증

임시 검증은 저장소 외부에서 수행했으며 운영 DB를 변경하지 않았다.

| 조건 | 확인 결과 |
| --- | --- |
| 기본 양식의 57개 고유 번호와 P/Q 사진 114개 | 사진·온도·대상 행 일치 |
| 30행 전후 행 높이를 15~150pt로 변경 | 저장·재로딩 후 앵커 일치 |
| 30행 앞의 일부 행 숨김 | 앵커·숨김 유지 |
| H30 비움 | 빈 행 이후에도 실제 행 번호 유지 |
| H30:H31 병합 | 이후 행의 좌표 유지 |
| Q29 기존 이미지 | 기존 사진 보호, 이후 행의 좌표 유지 |
| 완성 파일에 같은 사진 재입력 | 수정 전 4건 추가 → 수정 후 0건 추가 |
| 전체 번호·지역 생략 번호·네 자리 충돌·전체 번호 불일치 | 정확한 행 선택 또는 확인 오류 |
| 실제 브라우저 캔버스로 PNG→JPEG 압축 후 다운로드·재로딩 | 30·31·32·51·56행의 P/Q 사진 10개 모두 일치, 재입력 0건 |

사진 압축을 생략한 좌표 실험과 실제 브라우저 압축 실험을 구분했다. 후자에서는 원본 PNG와 엑셀 JPEG의 바이트가 다르더라도 같은 압축 결과를 통해 재입력을 탐지했다. 행 높이만 변경하는 실험에서 연속적인 한 행 이동은 재현되지 않았다.

## 후속 캡처와 수신 파일의 직접 대조

사용자는 원본을 구하지 못했고, 내려받은 뒤 행 삽입·삭제·정렬을 했는지도 확인되지 않는다고 답했다. 로컬 수신 폴더에서 `안산사조센터 일일 온도점검_261029.xlsx`를 발견해 별도 복사본으로만 조사했다. 원본은 수정하지 않았으며 파일·사진·개인 메타데이터는 저장소에 포함하지 않았다.

확인 파일은 73,624,798바이트, 사진 180개이며 SHA-256은 `c6b3d84fd3ff761905ccff0ce9c9f59f0e942bea29fb6c97ba4687e6f6b3d62c`이다. Q열 이미지의 실제 바이트를 추출해 차량번호를 눈으로 확인하고, 원본 drawing XML과 대조했다.

| 영수증 차량 | H열의 올바른 행 | 수신 파일에 저장된 사진 위치 |
| --- | --- | --- |
| 9740 | 29 | Q29, 아래 2055 사진과 중첩 |
| 2055 | 30 | Q29, 9740 사진 밑에 가려짐 |
| 3161 | 31 | Q29의 아래쪽 끝에서 시작해 대부분 30행을 차지 |
| 5293 | 32 | Q30의 아래쪽 끝에서 시작해 대부분 31행을 차지 |
| 2781 | 33 | Q32 |

3161 사진의 앵커는 0 기반 `from.row=28`, `rowOff=1264918`, 5293은 `from.row=29`, `rowOff=1264919`다. 해당 행 높이는 99.75pt이며 오프셋은 약 99.60pt이므로 사진의 본체가 다음 행에 놓인다. 단순히 `nativeRow + 1`만 읽으면 실제 배치를 잘못 해석할 수 있다. 2781은 `from.row=31`, `rowOff=0`이다. 마지막에 배치된 9740 사진이 2055 사진을 가리고 있어, 겹침과 연속 오배치를 함께 설명한다.

반면 K31의 `1.9`, J32/K32의 `-19.9 / 3.9`는 각 차량의 영수증 내용과 맞는다. 따라서 이 캡처는 사진과 온도가 함께 다른 차량에 매칭된 경우와 구분된다. 화면 표시만의 착시가 아니라 해당 파일 자체에 오배치가 저장돼 있다.

### 현재 출력 경로로 다시 저장한 결과

발견한 파일을 `matchOneTopWorkbook(buffer, [])` → `oneTopOutputBlob`으로 통과시키고 새 파일을 재로딩했다. 새 분석·사진 삽입을 하지 않아 기존 사진 처리만 분리한 실험이다.

- 사진 180개 모두 이미지 SHA-256, 시작·끝 앵커의 정수 행·열과 EMU 오프셋, 배치 방식이 동일했다.
- 모든 행 높이·숨김, 병합 범위, 인쇄 설정 및 검사한 A:R 중 Q열을 제외한 셀 값이 동일했다. 병합 범위의 XML 나열 순서만 달라져 집합으로 비교했다.
- Q열은 기존 온도가 있는 행의 공백 표시를 정규화할 수 있어 값 보존 비교에서 제외했다. 이미지 좌표 비교에서는 제외하지 않았다.
- 오배치와 중첩도 그대로 유지됐다. 새 사진 삽입은 0건이었다.

현재 신규 사진 삽입 코드는 행 오프셋 0을 기록한다. 발견 파일의 기존 사진은 오프셋과 겹침을 포함해 보존된다. 이 실험은 **현재 출력 경로가 이 파일의 기존 사진을 추가 이동시키지 않았음**을 보여준다. 이 파일이 과거 어느 단계에서 이렇게 됐는지는 증명하지 않는다. 독립 검토에서도 원본 drawing XML의 오배치·중첩과 동일한 한계를 확인했다.

## 현재 결론과 남은 한계

캡처의 오배치 패턴과 동일한 사진 좌표 및 중첩을 수신 파일에서 직접 확인했다. 이미 오배치된 파일을 입력하면 현재 처리 경로는 그 상태를 유지한다. 앞서 수정한 재입력 중복·차량번호 충돌 결함을 이번 캡처의 확정 원인으로 설명할 수 없다.

웹 입력 전부터 존재한 배치인지, 과거 출력 과정 또는 엑셀 저장·편집 과정에서 생겼는지는 입력·출력 쌍과 편집 이력이 없어 미확정이다. 모든 사진을 일괄 한 행 내리는 보정은 정상 사진과 겹친 사진을 손상할 수 있어 적용하지 않았다. 이 추가 조사는 처리 코드 수정이나 신고 사례 해결 완료를 의미하지 않는다.
