# 평택 배차 작업

목표는 CJ 당일 지시 물량을 기준으로 현장에서 유지하는 본인코스와 조정되는 용차·지원배송을 구별하고, 이력과 실제 주행 구간에 근거한 가배차를 담당자가 조정·저장하는 것이다. 차량수 최소화나 당일 실배차 정답 복사가 목적이 아니다.

기존 평택 가배차 화면(pyeongtaek-dispatch.html)에 CJ 당일 지시서 작업을 연결한다. 직접 입력·납품정보·주행 수집 작업은 같은 화면에서 전환하며 기존 기능을 유지한다. 기존 인증·센터·charter 권한, 코스·납품처·차량·거리 DB를 재사용한다. 별도 메뉴·테이블을 만들지 않는다. 가배차는 기존 pyeongtaek_dispatch_drafts와 revision 기반 저장 함수를 사용하고 확정 charter_trips를 덮어쓰지 않는다.

CJ 파일의 사조/한성 시트에서 상세 물량만 읽고 요약/총합계는 제외한다. 사조RAW의 차량명(지입/임시)과 DM마스터, 한성거래처마스터를 사용한다. 소수는 박스환산 단위이므로 보존한다. 동일 코드 또는 확인된 동일 하차 단위는 합산하며 주소만 같은 별개 납품처를 무조건 합치지 않는다. 실배차 파일은 기존 파서를 재사용하되 당일 코스·형태로 다시 묶어 비교하며 당일 정답을 추천 모델에 넣지 않는다.

본인코스 우선, 온전한 착지 우선 배정, 실제 상차한도와 CJ 참고량 구별을 기본 규칙으로 둔다. 한도 미확인은 본인코스 제안을 유지하고 검토 표시한다. 착지 전체 배정 후 실제 한도 대비 적재율이 기사별 분할 검토 기준(사용자 승인 임시 기본값 90%) 미만이면 남은 착지 일부를 실어 물량을 확보하고 초과분을 용차로 보낸다. 기준 이상이면 잔여 착지는 통째로 용차로 보낸다. 임시로 지정된 원본 코스와 외부 지정 배송은 구분한다. 이배송은 본인물량 후 실제 잔여 용량 및 시간, 확인된 지원 이력과 방향별 주행 경로를 만족할 때 후보로 제시하고 담당자가 선택한다. 여러 선택 후 누적 상태를 다시 검사한다.

이력은 배차일보다 앞선 기록만 사용한다. 같은 번호판의 별도 코스를 합치지 않는다. 기본 반복 묶음과 코스/권역 일관성을 우선하고 거리·시간은 적합성 및 동점 후보 검토에 사용한다. 조회한 주행 구간은 좌표 키를 검증하고 방향을 유지한다. 여러 실측 구간을 이어 만든 경로는 직접 실측과 구별한다. 연결이 없으면 미확인으로 표시하며 직선거리나 역방향 값을 실제 주행으로 표시하지 않는다.

화면: CJ 업로드/일자, DB·주행·이력 불러오기, 기사별 상차한도·휴무 설정, 가배차 실행, 코스별 착지/물량/근거/경로 확인, 착지 전체 이동·묶음 조정, 실배차 파일 대조, 가배차 저장/다시 열기, XLSX·JSON 내보내기. 원본 미일치·동일 착지 여러 배정·수량 차이와 경로/한도 미확인 상태를 표시한다. 잘못된 입력이나 저장 충돌은 기존 안을 유지한다.

검증은 첨부된 2026-10-19 두 원본으로 수량 보존·요약 제외·전체 착지 고유 배정·당일 정답 분리·코스 식별·물량 초과·고정차 활용·실측 방향/좌표/연결 여부를 확인한다. 기존 관련 검사와 빌드, 화면 동작도 확인한다. 실제 주소·기사·차량 개인정보가 포함된 파일/스냅샷은 제품 소스나 공개 정적 파일에 포함하지 않는다. JEV 키는 브라우저에 포함하지 않는다.

구현 순서: 1) 원본 대조·18,057 주행구간 감사 2) 입력 정규화·이력/거리 모델 3) 배차·수동조정·대조 4) 기존 화면 및 draft DB 연결 5) 실제 파일 재실행·검증·커밋/푸시.

## 2026-10-19 원본 검증 결과

- CJ 상세 338행, 14,936.94375 박스환산을 보존했다. 화주별 원출고일 10/18·10/19 혼재는 배차일 10/19와 구분해 표시한다.
- 현재 주소가 확인된 동일 하차 단위를 합산하면 301개 후보 착지다. 과거 동시 배차만으로 다른 주소를 합치지 않는다. 같은 주소의 다른 하차장은 담당자가 확인한다.
- 기준일 전 5,313개 이력, 53개 운행일을 조회했다. 코스 단위로 묶고 차량·톤수가 충돌하는 9개 과거 코스를 근거에서 제외했다.
- 593개 주소와 방향별 주행 18,057건을 전수 검사했다. 조회 시점 좌표 키가 유효한 기록은 18,057건이다. 이 사실이 모든 당일 착지의 연결을 보장하지는 않는다. 무한도 초기안 119개 묶음 중 33개만 주행이 모두 연결되고, 86개는 일부 연결 확인이 필요하다.
- 실배차 파일의 식별키 미연결은 0건이고, 합산 후보 착지 중 123개에 조정 기록이 연결된다. 비교는 실배차에 실제 기록된 원본 코드 범위만 합산하며, 수량 차이 5건을 별도 표시한다. 이는 배차 일치율이나 담당자 판단 재현율이 아니다.
- 실제 상차한도를 모르는 초기안은 본인코스를 유지한 검토안이다. 용차 후보 묶음 수를 확정 차량 대수로 해석하지 않는다.

JEV 검토는 부분 조정표를 전체 배송 실적으로 오해하거나 수량 차이를 차량 분할 이유로 추론하지 않도록 하는 데 반영했다. 후보 선택형 검토는 담당자의 의도를 입증하지 않는다. 자료에 없는 실제 상차한도·납품조건·당일 섭외 사유를 추가 호출로 단정할 수 없으므로, 이 부분은 제품의 확인·조정 항목으로 남긴다. JEV는 개발 검토에 사용하며 제품 실행 시 키나 JEV 호출이 필요하지 않다.

## 운영 흐름과 재검증

관리 허브 → 평택 가배차 → CJ 당일 지시서 배차에서 원본을 올리고 기준·주행·이력을 읽은 뒤 기사별 실제 한도·운행 여부를 확인한다. 가배차를 실행하고 코스별 근거와 검토 항목을 확인하며 착지 전체 이동·동일 하차 단위 합산·순서 조정을 한다. 필요하면 실배차 파일을 올려 차이를 대조하고 가배차를 저장하거나 XLSX로 출력한다.

직접 입력·납품정보·주행 수집 탭은 기존 기능을 유지한다. 납품정보에 저장한 OTD의 시작·마감·예약 조건을 기존 파서로 읽고, 이른 도착 대기시간도 이배송 추가시간에 포함한다. 기존 숫자 마감은 예약시간으로 바꾸지 않는다. 하차·검수·여유시간은 입력된 값만 사용한다.

저장안을 열면 현재 DB를 다시 읽기 전 저장·출력을 잠근다. 저장 시점과 현재의 납품정보·코스 기준을 비교하고 다르면 수동 조정을 유지하면서 재생성을 요구한다. 현재 기준이 같으면 수동 조정을 유지한 채 경로를 재검증한다. 같은 화면에서 납품정보나 주행 DB를 바꿔도 CJ 안의 검증 상태를 갱신한다. CJ 저장안과 기존 직접 입력 저장안은 형식별로 나누어 조회한다.

검증: 프로덕션 빌드, 변경 JS lint, 기존 파서·DB·정규화·다중 파일·통계 검사, 실제 두 파일을 사용한 브라우저 작업(업로드·전체 자료 조회·대조·이동·저장·복원·출력·권한·기존 화면 전환), 조건 변경 후 복원 우회 방지, 착지 단위 초과/본인차 활용/미확인 한도/OTD 대기·익일 조건/당일 이력 배제 회귀 검사를 수행했다. 브라우저 저장 검증은 DB 대체 응답으로 수행하여 실제 확정 배차 데이터를 변경하지 않았다.

## 배포 전 JEV·화면 검토

이배송은 최초 본인코스 착지 목록을 기준으로 주행·대기·하차 시간을 다시 계산하고, 모든 추가 착지의 누적 증가가 허용시간 안에 있을 때만 후보로 제시한다. 직전 추가 건과만 비교해 한도를 반복 우회하던 문제를 수정했다. 기준 목록이 없는 이전 저장안은 재생성 후 후보를 계산한다. 수동 조정으로 누적시간을 넘기면 코스 검토 항목에 표시한다.

고정차 한도는 차량조건에서 수정한 후 재생성한다. 카드에서 그룹 한도만 따로 변경하여 차량조건과 초과착지 판정이 어긋나던 경로를 제거했다. 실배차 대조는 선택 항목으로 접고 JSON·주행 확인은 보조 도구로 묶었다. 원본 코드의 내부 접두사는 화주명으로 표시한다.

JEV는 누적시간 사례와 상차한도 편집 정책을 검토했다(2개 질문, 입력 725·출력 109토큰). 별도 모델 회귀에서 본인코스 100분, 허용 30분에 첫 이배송 +20분은 허용하고 두 번째 누적 +40분은 제외되는지 확인했다. 기존 7개 검사·변경 JS lint·빌드·실제 파일 기반 13개 브라우저 흐름이 통과했다. 운영 사이트는 로그인 화면까지 확인했으며 인증 이후 작업과 저장은 실제 데이터/DB 대체 응답으로 검증했다.

## 조건부 분할 상차 (2026-10-19 규칙 수정)

기존 착지 전량 이동 원칙은 조건부로 변경한다. 온전한 본인 착지를 우선 배정하고, 실제 한도 대비 적재율이 분할 검토 기준 미만인 경우 남은 착지 중 첫 후보를 필요한 만큼 나눠 싣는다. 기본 기준 90%는 사용자 승인 임시값이며 이력으로 학습된 수치가 아니다. 기사별 0~100%로 조정할 수 있다. 0%는 자동 분할을 하지 않고 100%는 부족분이 있으면 분할한다. 변경 후 재생성한다.

- 1착지 120 / 한도 100 → 고정차 100, 임시차 20.
- A 30 + B 120 / 한도 100 → 고정차 A 30 + B 70, 임시차 B 50.
- 470 상차 + 잔여 착지 50 / 한도 500 → 94% 적재이므로 고정차 470 유지, 잔여 50 전체 임시차.

분할 배정 ID와 원본 착지 ID를 구분하고 원본 코드별 총수량 보존을 매번 검증한다. 실배차 대조는 분할분을 원본 착지로 다시 합쳐 실제 기록을 한번만 집계한다. 여러 원본 코드가 합쳐진 착지를 분할하면 코드별 물량을 비례 배분한 검토안으로 만들며 냉동·냉장 세부 수량은 추정하지 않는다. 품목별 실제 상차내역을 확인하도록 표시한다. 분할된 착지의 수동 합산은 막고 차량 조건 변경 후 재생성하도록 안내한다.

JEV 개발 검토에서 조건부 분할·임시 기준·원본 합계 보존을 확인했다(입력 924/출력 144토큰). 웹 실행 중 JEV를 호출하는 기능은 이번 수정에 포함하지 않는다. 후보 선정은 기존 본인코스 순서를 사용하며 JEV가 실제 과거 배차 이유를 추론해 선정했다고 표시하지 않는다.
